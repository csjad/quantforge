## 2. 数据库选型（D-002）

### 2.1 选型核心问题
"分析型查询与写入并发能否兼得"——本系统存在**回测任务并发读、数据同步并发写**的真实场景。

### 2.2 三方案对比（表5，工程正文原文数值；依据句为本轮补充）
| 维度（权重） | 方案甲 SQLite | 方案乙 PostgreSQL | 方案丙 DuckDB |
|---|---|---|---|
| 写入并发（0.25） | 弱，单写锁 | 强，多连接 | 中，适合批量导入 |
| 分析查询（0.30） | 中，需手工索引 | 强，索引与分区成熟 | 极强，列式扫描 |
| 部署成本（0.20） | 无，单文件 | 中，需容器与账号 | 无，嵌入式 |
| 运维难度（0.15） | 极低 | 中 | 低 |
| 生态兼容（0.10） | 高 | 极高 | 中，工具链较新 |
| 加权总分 | 3.4 | **4.2** | 3.9 |

依据句：SQLite单写锁会在批量导入时阻塞回测读，与"并发读+并发写"场景直接冲突；PostgreSQL的备份恢复、分区表、按时间范围查询三项为成熟能力，直接服务S14备份体系；DuckDB向量化执行适合即席聚合，工具链较新，不承担在线事务。

### 2.3 D-002 决策与混合存储三层（C-021 消解定稿）
**选定方案乙 PostgreSQL 16**（版本锁定，版本不一致时迁移脚本需重测——新增假设）。

混合存储三层定稿：
| 层 | 承载 | 职责 |
|---|---|---|
| **Parquet 分区文件** | bars_raw、bars_adj（逻辑表，物理为列式分区文件） | K线行情主存：写入吞吐高、按分区追加、列裁剪+谓词下推；不塞关系库行存（分钟线单表超亿行后DDL需数小时，单机用户无此耐心） |
| **PostgreSQL 16** | symbols、strategies、bt_tasks、bt_results、factors、risk_rules、snapshots、隔离表、审计表 | 在线读写：元数据、任务状态、结果摘要、因子缓存、风控规则、快照登记；事务与备份成熟 |
| **DuckDB** | 进程内即席引擎 | 跨分区聚合、临时核查、离线分析辅助，**不承担在线读写** |

SQLite 不承担核心职责，仅作离线交付包内的引导轻库（可选）。**K线不走PG行存的口径**：省事的代价是灾难，三层各司其职、不互相替代。

### 2.4 存储方案五选四（表7 摘要，工程正文深度展开）
| 方案 | 写入吞吐 | 扫描吞吐 | 部署 | 增量导入 | 结论 |
|---|---|---|---|---|---|
| 单文件CSV | 低（全文件重写） | 极低 | 极低 | 差（易重复行） | 仅作导入源 |
| SQLite单库 | 中（事务串行） | 中 | 低 | 中（需游标） | 元数据适用（本项目改由PG承担，仅交付包引导可选） |
| **Parquet分区** | 高（按分区追加） | 高（列裁剪+谓词下推） | 无服务 | 高（按日期分区覆盖） | **行情主选** |
| DuckDB单文件 | 高（批量写） | 高（向量化） | 无服务 | 中 | 即席查询适用 |

### 3.1 表清单与主键索引
| 表名 | 关键字段 | 主键与索引 | 说明 |

| bars_adj | symbol, trade_date, open, high, low, close, adj_factor, mode | 逻辑主键 symbol+trade_date+mode；物理分区同上 | 复权后行情，mode取qf/hf/none |

| strategies | id, name, version, params_json, code_path, created_at | 主键 id | 策略注册 |
| bt_tasks | id, strategy_id, params_snapshot, data_snapshot, status, created_at | 主键 id，索引 status | 回测任务 |
| bt_results | task_id, metrics_json, equity_curve_path, trades_path | 主键 task_id | 结果，曲线落文件 |
| factors | symbol, trade_date, factor_name, value | 主键 symbol+trade_date+factor_name | 因子缓存 |
| risk_rules | id, rule_type, params_json, enabled, updated_at | 主键 id | 风控规则 |

### 3.2 字段与索引细则（工程正文深度展开）
- **symbols**：以标的代码为主键；字段含交易所、上市日、退市日、板块、是否ST、行业标签、复权因子表指针；索引为 **板块+是否ST 复合索引**（标的池过滤是最高频查询）。
- **bars_raw/bars_adj**：按 **标的+年（日线）/ 标的+年月（分钟线）两级分区**。分区键用年月而非年的原因：重拉某月数据只覆盖一个小分区；年分区会重写整年数据。日线单标的单年约243根（体积约2.3KB/月分区→按年分区单分区约2.4万字节，可接受）；分钟线单标的单月约5000根，按标的+年月分区合适。**深入推导修正**：日线按"标的+年月"分区在日线上行不通——单标的单月约24根、体积约2.3KB，远小于文件系统最小分配单元，实际占用被放大4倍以上。
- **分钟线共用一表**：额外字段为 **周期标识**（1/5/15/30/60min），五种周期共用一表避免五套表五套代码；代价是查询必须带周期过滤条件，**该条件由引擎读取层强制注入，不允许调用方自行拼装**（防跨周期混算）。
- **快照/隔离/审计表**（S12/S15细化）：快照表主键=快照号；隔离记录主键=自增号、带来源批次号（可按批重放）；审计表主键=审计号。

### 3.3 关键 DDL（PostgreSQL 16，本阶段冻结结构）
```sql
-- 标的元信息（板块+是否ST复合索引用于池过滤）
CREATE TABLE symbols (
    symbol     VARCHAR(16) PRIMARY KEY,
    name       VARCHAR(64) NOT NULL,
    board      VARCHAR(16) NOT NULL,      -- 主板/创业板/科创板
    list_date  DATE, delist_date DATE,
    is_st      BOOLEAN NOT NULL DEFAULT FALSE,
    industry   VARCHAR(32),
    adj_ptr    VARCHAR(64),              -- 复权因子表指针
    updated_at TIMESTAMP NOT NULL DEFAULT now()
);
CREATE INDEX idx_symbols_board_st ON symbols(board, is_st);

-- 回测任务（status索引，五态：待排队/运行中/成功/失败/取消）
CREATE TABLE bt_tasks (
    id              BIGSERIAL PRIMARY KEY,
    strategy_id     INTEGER NOT NULL REFERENCES strategies(id),
    params_snapshot TEXT NOT NULL,        -- 参数快照JSON
    data_snapshot   VARCHAR(64) NOT NULL, -- 数据快照号
    status          VARCHAR(16) NOT NULL,
    created_at      TIMESTAMP NOT NULL DEFAULT now()
);
CREATE INDEX idx_bt_tasks_status ON bt_tasks(status);

-- 结果摘要（曲线/逐笔落文件，路径留存）
CREATE TABLE bt_results (
    task_id          BIGINT PRIMARY KEY REFERENCES bt_tasks(id),
    metrics_json     TEXT NOT NULL,
    equity_curve_path TEXT NOT NULL,
    trades_path      TEXT NOT NULL
);

-- 因子缓存（主键含因子名，防同标的同日同名因子覆盖）
CREATE TABLE factors (
    symbol    VARCHAR(16) NOT NULL,
    trade_date DATE NOT NULL,
    factor_name VARCHAR(64) NOT NULL,
    value     DOUBLE PRECISION NOT NULL,
    PRIMARY KEY (symbol, trade_date, factor_name)
);

-- 风控规则
CREATE TABLE risk_rules (
    id          BIGSERIAL PRIMARY KEY,
    rule_type   VARCHAR(32) NOT NULL,
    params_json TEXT NOT NULL,
    enabled     BOOLEAN NOT NULL DEFAULT TRUE,
    updated_at  TIMESTAMP NOT NULL DEFAULT now()
);
-- bars_raw/bars_adj 为 Parquet 分区文件，DDL仅作逻辑契约，物理实现见§7分区策略
```

## 4. 复权计算三步法（R-D-003）

1. **取事件表**：从原始除权除息事件表取出标的的调整事件，按事件日期排序。
2. **累乘因子**：按事件顺序累乘调整系数，得到因子序列。前复权以最新价为基准，因子为各期累计调整量的倒数；后复权以首日为基准，因子为累计正向调整。
3. **按模式应用**：按模式（qf前复权/hf后复权/none不复权）对原始价格乘以因子，**成交量反向缩放**。
- **校验方法**：复权后相邻两日收益率与原始收益率在除权日应一致；不一致说明因子缺失，须回填并阻断该标的入库登记（失败模式表第3条）。
- **硬性约束**：bars_adj 的 mode 字段在查询时**必须显式传入，禁止默认值**（A3评审条件），避免同一任务混用两种复权口径。

## 5. 数据清洗规则（R-D-004，六条全部通过才允许入库）
1. 最高价 ≥ max(收盘价, 开盘价)
2. 最低价 ≤ min(收盘价, 开盘价)
3. 成交量与成交额均非负
4. 相邻日收盘价跳变超过20%（非除权事件）标为可疑
5. 交易日与交易所日历一致
6. 同一标的同一日期不得重复（唯一键=symbol+trade_date[+mode]）
- **处置**：不通过的记录写入**隔离表**并记录原因，**不得静默丢弃**（A2评审条件：拉取失败不得静默跳过，必须记录缺失标的清单，否则标的池静默缩水——缩水后的结果表面正常，是最难发现的一类失真）。
- **与S00十二条校验规则的关系**：本六条为工程正文权威口径，S00的12条为其逐条细分展开，实现时以六条为入库门禁、12条为字段级细化。

## 6. 增量同步逻辑（R-D-002）
1. **缺口计算**：比对本地最大日期与远端最新日期，算出缺口区间。
2. **拉取策略**：缺口小于阈值→区间拉取；大于阈值→全量分片重拉。
3. **共用校验管道**：拉取结果进临时区，走与批量导入**完全相同**的校验管道——增量与全量若各走一套，两套规则必然随时间漂移，漂移后同一份数据因入口不同而结论不同。
4. **标的池白名单（C-001闭环）**：入库层强制校验 symbol ∈ 当前池，非池内标的拒绝写入并告警（防止分钟线被写入全市场导致磁盘超限）。
5. **频控与退避**：在线两套源，一套按积分限制默认每分钟200次、一套免费接口多变默认每分钟60次；失败自动退避3次（1/2/4秒递增），触发封禁冷却。

## 7. 分区策略与查询模式

### 7.1 分区
- bars_raw/bars_adj：**日线按 标的+年 分区**（单分区约243根/标的，体积约2.3KB，实际占用约4个簇可接受）；**分钟线按 标的+年月 分区**（单标的单月约5000根）。
- 分区收益：删除与归档可按年/月操作，避免全表扫描；代价是跨年查询需并行扫描多分区，**S02 需标注查询改写规则**。

### 7.2 三类查询与索引取向
| 查询类型 | 占比 | 取向 |
|---|---|---|
| 单标的区间扫描 | 约八成 | 分区裁剪+列裁剪，不做行级索引 |
| 全池某日截面（横截面因子） | 中 | 日期倒排索引：元数据层登记"某日期在哪些分区内"，避免全库扫描 |
| 结果回溯（报告） | 低 | 按任务标识直查 bt_results 摘要表 |

### 7.3 明确拒绝的查询
**跨全池跨十年的横截面统计拒绝实时查询**，改为离线预聚合，结果落因子缓存。拒绝实时查询不是能力不足，而是刻意的边界：个人级平台若允许任意跨十年全池扫描，一次误操作就让界面卡死一分钟以上，体验崩塌往往从一次卡死开始。

## 8. 三条写入路径

| 路径 | 流程 | 关键设计 |
|---|---|---|
| ① 批量导入 | 文件落临时区→逐文件流式解析→按标的分片校验→写分区→更新元信息登记→生成快照号 | 以**标的分片为单位提交**；单标的分片失败不回滚其他标的，但必须在失败清单登记——避免"99个标的成功、1个静默丢失"的假完整 |
| ② 在线增量 | 缺口计算→区间拉取/分片重拉→临时区→与路径一同一条校验管道 | 增量与全量**共用校验管道**（见§6） |
| ③ 快照回滚 | 快照=元信息+分区文件清单+校验和 | 回滚=按清单**重挂分区**而非复制数据：秒级完成，磁盘不翻倍 |

## 9. 失败模式与处置（表8）
| 失败模式 | 触发条件 | 观测特征 | 处置 |
|---|---|---|---|
| 分区文件半写 | 导入中断 | 分区内行数少于登记值 | 校验和比对失败则整分区重写 |
| 元信息与分区不一致 | 手工删文件 | 查询返回空但登记存在 | 启动自检修复登记 |
| 复权因子缺失 | 数据源未提供 | 除权日收益异常放大 | 阻断该标的入库并登记 |
| 周期字段污染 | 调用方漏传周期 | 跨周期混算 | 读取层强制注入并断言 |
| 快照指向失效 | 回滚后又增量导入 | 回滚结果被新数据覆盖 | 快照加时间戳，回滚后自动新建基线快照 |

共同思路：**让不一致暴露在启动时，而不是在回测结果里**——回测结果里的不一致没有报错，只有一条看起来正常但偏高的收益曲线，会被当成策略有效性的证据。

## 10. 容量与性能测算（深入推导口径）

### 10.1 分区文件实际体积
- 单标的日线20年约5000根×96B≈480KB；**按月分区不可行**（单标的单月24根≈2.3KB，小于文件系统最小分配单元，实际占用放大4倍）→ 日线按**标的+年**分区（单分区约2.4万字节，约4个簇，可接受）。分钟线按**标的+月**分区（单标的单月约5000根）。

### 10.2 导入耗时分段（500标的×5年日线=62.5万根）
| 段 | 耗时 |
|---|---|
| 解析 | 约40秒 |
| 校验 | 约15秒 |
| 写入 | 约25秒 |
| 登记 | 约3秒 |
| 快照 | 约2秒 |
| **合计** | **约85秒**（P-05目标≤3分钟） |
- 若实测超3分钟，瓶颈通常在写入分区的打开关闭次数而非解析——处置：合并小分区、批量提交。

### 10.3 查询耗时三段（单标的5年日线）
- 定位分区 <1毫秒；读取约5毫秒；反序列化与转表约30毫秒。**瓶颈在反序列化**——列裁剪与类型转换一次做完，不能先转通用表再筛选。
- 全池某日截面：按日期倒排索引定位500个分区、逐分区读一根，实测约**120毫秒**。该数字决定横截面因子**必须离线预计算**，实时做会让面板明显卡顿。

### 10.4 索引开销
索引按1倍体积计（日线2.4GB→含索引4.8GB），具体开销在S02接入真实数据后实测校准。
