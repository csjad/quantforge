## 2. 账户模型（三层结构）

### 2.1 三层字段定义
| 层 | 字段 | 说明 |
|---|---|---|
| 现金层 | 可用、冻结、在途 | 可用=可动用资金；冻结=已提交未成交买单占用的资金；在途=已提交未成交卖单对应的持仓数量占用（以股数计） |
| 持仓层 | 标的、数量、成本、可卖数量 | 成本=买入含费均价；可卖数量=T+1解锁后可卖出的数量 |
| 权益层 | 现金+持仓市值 | 市值按本根收盘价×数量估算 |

### 2.2 T+1 关键约束（写错=回测收益凭空增加）
- 当日买入的持仓在**次日才可卖出**；资金在当日买入成交后即从可用转为持仓占用，**不得重复使用**。
- 该规则若写错，等价于给了策略无限资金——回测收益会凭空增加。

### 2.3 三条守恒式（每根K线结束时校验，逐笔校验而非逐日）
1. **现金守恒**：初始资金 = 期末权益 − 区间内所有已实现盈亏 − 未实现盈亏 − 全部成本之和
2. **现金层守恒**：任一时刻 可用 + 冻结 + 在途 = 现金总额
3. **持仓守恒**：可卖数量 + 冻结数量 = 持仓数量

三条式子是发现"资金凭空出现"的唯一手段：记账错误的典型表现是权益曲线**缓慢上漂**，单日看不出来，一年下来多出百分之几，被误认为策略的alpha。**逐笔校验而非逐日**——逐日校验会让日内错误互相抵消（同日既多扣佣金又少扣过户费，日终合计凑巧接近），逐笔必然暴露。

## 3. 引擎状态机（六状态、七转移）

| 状态 | 说明 |
|---|---|
| 初始化 → 预热 | 条件：数据装载完成且**指标预热窗口满足** |
| 预热 → 运行 | 条件：账户资金就位且首个可交易日确定 |
| 运行 → 暂停 | 仅在人工干预或熔断触发时发生 |
| 暂停 → 运行 | 需人工确认 |
| 运行 → 终止 | 最后一根K线处理完毕 |
| 终止 → 归档 | 结果落盘与摘要登记完成 |

**任何越级转移都被视为缺陷**——越级意味着某个必要步骤被跳过，而跳过的步骤往往正是资金校验或数据完整性校验。

**预热窗口**：不是常数，而是**各指标回看期与拟合窗口的最大值**。用200日均线→预热至少200根；若还用训练段标准化→预热再加训练段长度。把预热当"随便给50根就够"是本项目早期最严重的一类错误：不报错，只让最前面若干根信号凭空消失，而消失的信号通常恰好包含建仓时点。

## 4. 单根K线的九步时序（顺序有讲究）

| 步 | 动作 | 要点 |
|---|---|---|
| 1 | 交易日判断 | 非交易日直接跳到下一根 |
| 2 | 停牌判断 | 停牌则跳过撮合但**保留持仓估值** |
| 3 | 处理昨夜委托 | 按**开盘价**与滑点撮合 |
| 4 | 涨跌停判定 | 一字板且方向不利者一律不成交，保留委托至当日收盘后**作废** |
| 5 | 更新持仓与现金 | 按成交结果更新，计算成本与费用 |
| 6 | T+1解锁 | 把昨日买入的可卖数量解冻（供当日卖出委托） |
| 7 | 计算当日信号 | 指标值**只能用到本根收盘，不得触碰下一根** |
| 8 | 风控裁剪信号 | 按风控规则裁剪，生成**次日委托** |
| 9 | 权益快照与日志 | 记录权益快照与全部中间量，写事件日志 |

**顺序论证**：撮合在信号之前，是因为A股按次日开盘成交，本根收盘产生的信号只能用于次日；若把信号计算放在撮合之前，实现者极易顺手用当根收盘价成交——**这正是未来函数最常见的入口**（呼应 S00-A3 禁令：代码中不得存在当根收盘成交路径）。

## 5. 成交判定与约束

### 5.1 成交判定
- **买单**：委托价不低于本根最低价 且 标的未停牌 → 可成交
- **卖单**：委托价不高于本根最高价 → 可成交
- **成交价**：**统一按开盘价成交**（C-026 消解定案，见§9），滑点方向对买方加、对卖方减

### 5.2 涨跌停三情形
| 情形 | 买单 | 卖单 |
|---|---|---|
| 开盘即涨停且全天封住 | **不成交** | 按涨停价成交 |
| 开盘即跌停且全天封住 | 按跌停价成交 | **不成交** |
| 盘中触及涨跌停但打开 | 按委托价与实际价格区间正常撮合 | 同左 |

- 若开盘价高于涨停价 → 视为数据异常，**交由 S02 校验层处理，不在引擎内消化**。

### 5.3 停牌处理
停牌期间：**不撮合、不计市值变动、不生成除权处理**；委托不撮合、不作废、**不顺延超过5个交易日，超期作废并记录**。

### 5.4 五项成交约束
1. **整手约束**：买入数量须为100股整数倍；卖出允许零股但仅限清仓。
2. **资金约束**：可用资金不足时，按可用资金**反算最大可买整手数**，而不是直接拒单——拒单会让回测少一笔本该发生的成交，低估策略交易频率。
3. **价格约束**：成交价=开盘价+滑点，滑点方向买方加、卖方减。
4. **停牌约束**：见§5.3。
5. **涨跌停约束**：见§5.2。

## 7. 滑点模型（三方案对比，D-004 终选）

| 维度（权重） | 方案甲 固定滑点 | 方案乙 波动比例滑点 | 方案丙 盘口分层滑点 |
|---|---|---|---|
| 实现复杂度（0.25） | 极低，一个常数 | 中，需当日振幅率 | 高，需分档逻辑 |
| 保守性（0.30） | 高，恒定保守 | 中，波动大时偏保守、平稳时偏乐观 | 中，分档近似 |
| 数据依赖（0.20） | 无 | 当日开高低收 | 当日成交量/成交额 |
| 可复现性（0.15） | 强，报告可精确复算 | 强 | 中，分档边界敏感 |
| 切换成本（0.10） | 默认 | 可选 | 可选 |
| 加权总分 | **4.3** | 3.4 | 3.2 |

**D-004 决策**：默认方案甲（固定每边1‰）；方案乙、丙作为可切换模型。
- 方案乙定义：滑点率 = k × (当日振幅/前收)，k默认0.25，封顶2‰。
- 方案丙定义：按委托股数占当日成交量比例分三档（<1%、1~5%、>5%），滑点率0.5‰/1‰/2‰——日线无真实盘口，以成交量近似盘口深度。
- 切换方式：回测任务参数 `slippage_model = fixed|volatility|depth`，报告首页强制打印所用模型与参数（可复现优先于高性能）。

## 8. 委托队列、订单结构与每日结算

### 8.1 订单对象结构
| 字段 | 说明 |
|---|---|
| order_id | 唯一订单号 |
| symbol / side / quantity | 标的/买或卖/数量 |
| price（委托价） | 记录留存；**撮合按开盘价**（C-026） |
| status | 待撮合/部分成交/已成交/已拒/已作废 |
| created_bar | 生成信号的K线索引（可溯源） |
| reason | 拒单原因（如"资金不足一手"） |

### 8.2 委托队列
按标的分组FIFO；**当日委托当日有效**，收盘后未成交委托作废（一字板保留至收盘后作废，见§4步4）。

### 8.3 每日结算
收盘更新持仓市值（收盘价×数量）→ 记录权益快照 → **三条守恒式逐笔校验** → 写事件日志。每一笔委托、成交、拒单、作废均留完整日志（含K线索引），满足"任一笔成交可回溯到原始K线"（R-E-006）。

### 8.4 回测时钟
事件驱动，以K线为步长；交易日历驱动（S01交易日历）；集合竞价以开盘价成交（C-026）。
**【多周期扩展段落（C-037 回溯，S32 新增）】**：多周期模式下时钟扩展为——**主时钟取最小周期，大周期在小周期推进到边界时触发一次**；大周期K线收盘时间为小周期时间边界，小周期在边界前只能看到已完成的大周期K线，未完成的不可见（对齐严格按时间戳，不允许按K线序号对齐）。单周期模式行为不变。

## 9. 冲突 C-026｜成交价歧义（工程正文S03原生，项目编号顺延）

- 发现阶段：工程正文S03 → 项目S03（工程正文内部编号C-002，项目编号因C-002已被架构冲突占用，顺延为C-026）
- 冲突原文甲：S00规定成交价为下一根开盘价
- 冲突原文乙：本阶段撮合条件使用委托价与实际价格区间比较，跳空情形下产生歧义（跳空低开时买单应以开盘价成交还是以委托价成交）
- 量化差值：跳空情形下成交价口径不同（开盘价 vs 委托价）
- 风险等级：中
- 失效后果：跳空日成交价失真，"委托价优于开盘价"时免费获得价差
- 方案1：统一按开盘价成交并忽略委托价（更接近真实集合竞价）
- 方案2：按委托价成交（更保守，成本更低）
- 方案对比：方案1契合A股日线回测集合竞价主流做法，且避免免费获得价差的失真；方案2在跳空低开时会系统性低估成交价
- **选定方案：方案1（统一按开盘价成交）**
- 需回溯修改的清单：S05策略下单接口说明、S19教程示例、本设计§4步3/§5.1

## 12. 深入推导：一笔完整交易的数字走查

设账户初始¥100,000，标的A前收10.00元，当日开盘10.05元，策略昨日收盘给出买入信号，仓位上限30%。

1. 目标金额 = 100,000×30% = **¥30,000**
2. 可买数量 = 目标金额 ÷ (开盘价×(1+滑点)) = 30,000 ÷ (10.05×1.001) = 30,000 ÷ 10.06005 ≈ **2982股**，向下取整到百股 = **2900股**
   - 勘误说明：工程正文原文写"2981股向下取整为2800股"，复算2982→2900，原文存在100股笔误，本文档以复算值为准（数值优先原则）。
3. 成交金额 = 2900×10.05 = **¥29,145**
4. 滑点成本 = 2900×10.05×0.001 = **¥29.15**
5. 佣金 = 29,145×0.00025 = **¥7.29**（>5元最低值，取7.29）
6. 过户费 = 29,145×0.00001 = **¥0.29**（沪市方向）
7. 合计支出 = 29,145 + 29.15 + 7.29 + 0.29 = **¥29,181.73**
8. 校验：可用资金 = 100,000 − 29,181.73 = **¥70,818.27**，冻结归零，持仓市值按收盘估
9. T+1：当日买入2900股记入不可卖，次日开盘前解锁
10. 次日卖出：可卖数量2900股，按次日开盘价−滑点成交，印花税0.5‰、佣金0.25‰（不低于5元）

**走查价值**：把全部费率参数一次用上，任何一项被写死或漏乘，最终数字都会与手工值偏差；偏差在单笔上只有几元量级，很容易被忽略，只能靠对账式校验发现。

## 13. 边界：资金刚好不足一手

- 可用¥9,900，标的价¥10，一手含费按 100股×10元 + 佣金5元 + 过户费0.1元 + 滑点1元 = **¥1006.1**（复算值；工程正文原文"1001元"为取整口径笔误，已勘误登记）。
- 9,900 ÷ 1006.1 ≈ 9.84 → 可买**9手**，余 9,900 − 9×1,006.1 = **¥845.1**。
- 可用¥990 < 一手含费 → **信号作废**，记录原因"资金不足一手"。
- **不允许"融通"或"允许零股买入"**——融通会让回测资金曲线出现平台不需要的假设。
- **记录原因这一点很重要**：若无记录，使用者会看到"信号产生了但没成交"然后怀疑撮合失效；有了原因字段，界面能直接显示"资金不足一手"，争议立刻消失。
