## 2. 插件接口规范（四钩子 + 五导出）

**策略以单个 Python 文件接入，必须导出五样东西**：

| 导出 | 职责 |
|---|---|
| **标识** | 策略唯一名称，用于日志与结果归属 |
| **参数模式** | 声明每个参数的名称、类型、默认值、上下界、步长；**寻优器（S06）据此生成组合** |
| **初始化钩子** | 预热前调用一次，建立策略自有缓存 |
| **逐根回调（on_bar）** | 每根K线调用一次，入参只含**切片视图 + 只读账户快照** |
| **结束钩子（on_close）** | 终止时调用一次，释放资源与落盘统计 |

**四钩子生命周期**（对应阶段定义：初始化/on_bar/on_order/on_close）：初始化→逐根行情回调→成交回调（on_order，更新策略内部状态）→收尾（on_close，输出统计）。

**刻意不给策略三样东西**：
1. **写权限**——策略只需产出信号，任何落盘需求由框架代劳；允许写文件，一个误写就能覆盖结果库；
2. **网络权限**——回测必须可离线复现，联网策略的复现性无法保证；
3. **跨标的随机访问**——一旦允许，横截面统计会被简化为逐标的循环；正确做法是走 S04 批量因子接口，两者性能差一个数量级。

**上下文对象（沙箱第一层，也是最有效的一层）**：插件内**不得直接访问数据库**，所有数据通过上下文对象提供；**上下文按日期截断，物理上只能取到当前K线及之前的数据**。任何越界读取直接抛异常并记录违规。

## 3. 参数模式与校验（拒绝而非截断）

- **类型仅五种**：整数、浮点、布尔、枚举、字符串选项。
- 每个参数必须给**上下界与默认值**。
- **两层校验**：
  - **静态校验**：检查声明本身是否自相矛盾（下界>上界、枚举默认值不在枚举内等），在策略注册时执行；
  - **运行期校验**：检查实际传入值是否落在界内，**越界直接拒绝并回显允许范围**。
- **拒绝而非截断是有意的选择**：截断看起来更友好，但它会让使用者在不知情的情况下跑了一个与自己设定不同的参数；寻优器恰恰靠参数精确性保证可复现，**截断等于在源头污染可复现性**。

## 4. 信号去重与防抖（三规则）

1. **持仓期去重**：同一标的同方向信号在持仓期间**不重复触发**；
2. **覆盖规则**：信号生成后进入队列，若下一根K线开盘前被更新信号覆盖，**以最后一条为准**；
3. **先平后开**：连续三根K线出现相反信号时，按**"先平后开"**顺序执行，**不允许反手直接翻仓**——避免回测中出现现实中难以实现的瞬时反向。

## 5. 沙箱四道边界

| 边界 | 实施 | 拦截点 |
|---|---|---|
| **第一道 进程隔离** | 策略在**独立子进程**中运行，崩溃不拖垮主进程（D-001 单体分层下的执行隔离） | 子进程崩溃→主进程≤10秒重启Worker，任务回队列断点续跑（RL-04） |
| **第二道 文件边界** | 子进程工作目录限定在**临时目录**，数据目录**只读挂载** | 替换打开函数，路径规范化后检查是否落在白名单根之下 |
| **第三道 网络边界** | 子进程**禁止出站**，运行期**屏蔽套接字创建**并记录违规尝试 | 套接字创建挂钩 |
| **第四道 资源边界** | 内存与运行时长设上限，超限即终止并标记该次回测失败 | 内存水位/超时看门狗 |

**第三道最易被绕过**（有些第三方库在**导入时**就会尝试联网）→ 处置为**导入期白名单**：只允许纯计算库，**导入失败直接报错而不是静默降级**。理由：静默降级会让回测在联网成功与失败两种情况下给出不同结果，**这种不一致比装不上库严重得多**。（白名单基线：math/statistics/datetime/collections/itertools/functools/numpy/pandas + 平台API，SEC-07。）

**超时与内存上限取值**：
| 任务类型 | 超时 | 内存上限（单任务峰值×1.5倍） |
|---|---|---|
| 日线单标的 | **30秒** | 约**2.2GB** |
| 60分钟线 | **90秒** | 约**6GB** |
| 遍历单组 | **300秒** | 同任务级 |

取1.5倍的理由：策略自有缓存会叠加，留余量后**正常策略不会被误杀**。**误杀的代价比放行高**：误杀让正常回测失败，使用者会认为是平台缺陷；放行只让异常策略多吃内存，后面的护栏仍会拦。**上限宁可宽松**。

## 6. 违规处理与拦截日志

- 违规处理：**抛出异常并终止该策略的本次任务**，记录违规类型与调用栈。
- **拦截日志五项**：时间、策略标识、违规类型、尝试的目标、**调用栈前三层**。
- 前三层调用栈是关键：能区分**策略代码直接违规**（策略作者的问题）与**第三方库导入时违规**（依赖选择的问题）——两者处置完全不同。若日志只写"发生违规"，使用者无法判断改代码还是换库，最后往往删掉整段逻辑，反而丢掉正常功能。

## 7. 表15 沙箱逃逸用例（S15 安全审计复用，本阶段定义）

| 用例 | 手段 | 期望结果 |
|---|---|---|
| 文件越权读 | 打开上级目录行情库（`../`） | 拒绝并记录 |
| 文件越权写 | 写结果目录 | 拒绝并记录 |
| 网络外联 | 创建套接字 | 拒绝并记录 |
| 资源耗尽 | 申请超限内存 | 终止并标记失败 |
| 无限循环 | 长时不返回 | 超时终止 |

**四种逃逸形态的代码长相**：读上级目录（相对路径`../`）、写任意位置（写模式指向临时目录之外）、联网（套接字或带网络库）、绕过（动态加载别处模块）。共同特征是"**看起来正常的库调用**"——因此**拦截不能靠关键词扫描源码，只能靠运行期挂钩**；挂钩代价性能下降**不超过3%**，可接受。

## 8. 沙箱目标声明（教程必须说清）

**沙箱的目标不是防住专业攻击者，而是防住"策略代码写错导致的越权操作"**。这一点在教程中必须说清，避免买家误解为安全产品。

## 9. 沙箱与回放的冲突（V2 复核点）

回放功能需要读取状态序列，而状态序列含账户信息。若允许策略读取账户，等于给了策略"看牌"的能力，策略可据此构造不现实的行为。**处置：回放只由面板读取，策略进程无此接口**。该隔离在 V2 加入回放功能（S23）时**专门复核一次**——新功能最容易顺手复用已有接口。

## 10. 冲突 C-027｜因子批量读取 vs 策略单点读取（工程正文S05原生，项目编号顺延）

- 发现阶段：工程正文S05内部（S04 vs S05）→ 项目S05（工程正文内部编号C-003；项目C-003已被滑点冲突占用，顺延为C-027）
- 冲突原文甲：S04 要求因子可批量预计算
- 冲突原文乙：S05 要求策略只能看到当前K线
- 量化差值：接口层面批量读取 vs 单点读取的暴露面不同
- 风险等级：中
- 失效后果：若暴露批量读取，策略可一次性拿到整段未来数据，未来函数防线失守
- 方案1：因子预计算在内核完成，策略只能**按日期索引读取单点值**，接口不暴露批量读取方法
- 方案2：策略侧自行做批量读取
- 方案对比：方案1把批量计算留在内核（S04 性能目标），策略侧只拿单点（物理截断生效）；方案2破坏截断
- **选定方案：方案1**
- 需回溯修改的清单：S04 因子读取接口说明（已对齐）、S05 上下文契约（已写入§2）
- 修改完成确认标记：已完成
