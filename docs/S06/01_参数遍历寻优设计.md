## 2. 任务队列与调度器

### 2.1 队列结构
- 任务队列采用 **Redis 列表结构**（端口6379，S00-01 已预留），工作进程以**阻塞方式取任务**。
- **分片表落 PostgreSQL 持久化**（bt_tasks 扩展：参数组合总数 + 已完成索引 + 参数哈希）。队列（Redis）负责分发，分片表（PG）负责状态——**"不依赖任何内存状态"的实现路径**：Redis 崩溃重建队列后，任务仍可从 PG 分片表索引继续。

### 2.2 并发调度
- **并发数默认 = 物理核数 − 4**（C-034 修订：原核数−2 在八核机实测并发4即内存超限；S17 联合审计压测实测后修订）。
- **按任务类型分级**：日线任务可并发到上限；**分钟线任务并发减半**。原因不是 CPU，而是内存：分钟线单任务峰值可达数 GB，多任务同时跑触发交换，**一旦开始交换，整体吞吐降到原来的十分之一，比串行还慢**。
- 并发与单任务内存上限**双约束**：内存使用率≥85%告警、≥95%拒绝新任务入队（S00-01 资源上限表）。

### 2.3 优先级与超时熔断
- 任务优先级：手动提交 > 遍历任务 > 补采任务（可配，默认此序）。
- 超时熔断：单任务超时 30分钟（B-14），遍历单组超时 **300秒**（S05 沙箱资源边界）；超时任务标记失败并记录断点。

## 3. 三套寻优策略对比（表16）与 D-005 决策

| 维度（权重） | 网格遍历 | 随机搜索 | 贝叶斯优化 |
|---|---|---|---|
| 覆盖完整性（0.30） | 完整 | 概率覆盖 | 不保证 |
| 参数维度容忍（0.25） | 差，维度爆炸 | 好 | 好 |
| 实现复杂度（0.20） | 低 | 低 | 高 |
| 可解释性（0.15） | 高 | 中 | 低 |
| 结果稳定性（0.10） | 高 | 中 | 依赖先验 |
| 加权总分 | 3.8 | **4.1** | 3.2 |

**D-005 决策：V1 采用随机搜索为主、网格遍历为对照。** 理由：三参数以上时网格组合数呈指数增长，同等预算下随机搜索的期望覆盖更好；网格保留用于**两参数以内的穷举**，便于教学演示与结果可视化。**贝叶斯优化留到 V3**，与模型模块一并实现。

**搜索空间三道裁剪**（遍历的第一道闸不是算法，而是空间规模）：
1. **步长裁剪**：连续参数按步长离散（步长默认=区间/10，B-12）；
2. **边界裁剪**：按经济含义剔除明显无意义的区间（如窗口不能为负、倍数不能为0）；
3. **相关性裁剪**：对高度相关参数做降维——判断依据不是统计相关性，而是**经济等价性**。双均线快慢窗口同时缩放形状几乎不变，此时在"**快慢比 + 基准窗口**"两个维度遍历，而非快窗口/慢窗口两个原始维度——**1000组可压缩到约200组，且不损失有效信息**。

## 4. 任务分片与断点续跑

### 4.1 分片粒度与标识
- 分片粒度：**一组参数一任务**。
- 任务标识 = **策略标识 + 参数哈希 + 数据快照号**（三段绑定，防外部修改导致续跑错位——分片表与参数快照绑定哈希）。

### 4.2 续跑三状态
| 状态 | 含义 | 重启后处理 |
|---|---|---|
| 待执行 | 未开始 | 继续排队 |
| 执行中 | 正在跑 | **一律回退为待执行**（无法确认是否真正完成） |
| 已完成 | 已落盘 | 按**结果文件存在性 + 校验和**双重确认 |

### 4.3 硬规则
**不允许把执行中的任务直接标为已完成来省时间**。省下的时间是几十秒，代价是结果集里出现一组"有记录但结果文件为空"的参数——这类参数一旦被寻优器读入并排序，**会把最优点指向一个不存在的组合**。

## 5. 参数边界约束与结果聚合

- **参数边界约束配置**：每个参数的上下界/步长由 S05 参数模式声明（拒绝而非截断的原则延续——寻优器生成的组合必须全部落在声明界内）。
- **寻优结果聚合**：每组参数输出**全部绩效指标**（12项验收基线，C-018），**不只有收益率**；聚合排序按多指标加权（默认：年化收益40% + 夏普30% + 最大回撤30%，权重可配），并附过拟合标记（S06-02）。

## 6. 寻优性能实测口径（表17，供 S16 反算 A1 硬指标）

| 场景 | 组数 | 单组耗时 | 总耗时 | 判定 |
|---|---|---|---|---|
| 日线单标的 | 100 | 约3秒 | 约5分钟 | **达标**（P-04锚点：100组≤8分钟） |
| 日线池内10标的 | 100 | 约20秒 | 约33分钟 | 需分片 |
| 日线池内500标的 | 100 | 约15分钟 | 不可行 | **改为抽样标的** |
| 60分钟线单标的 | 100 | 约12秒 | 约20分钟 | 达标 |

**工程结论（A1 强制要求写入）**：全池500标的的参数遍历必须改为**"抽样加复核"**——先在**50只抽样标的**上遍历，取前20组再到全池复核。**这条结论推翻了"遍历就是全部跑一遍"的直觉**。

**抽样复核误差带**（深入推导）：50只抽样遍历→500全池复核，两组夏普之差通常在**1~3成**之间；复核后夏普反超抽样属正常波动；**若复核后骤降为负数，说明抽样标的与全池分布差异过大，应扩大抽样到150只重做，而不是接受全池结果**。
