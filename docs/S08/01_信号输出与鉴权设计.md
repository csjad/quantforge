## 2. 信号对象结构（对象层九字段 + 接口层十字段）

### 2.1 对象层（内部信号对象，技术正文九字段）
| 字段 | 说明 |
|---|---|
| 信号标识 | 唯一ID |
| 标的 | 标的代码 |
| 方向 | 买/卖 |
| 策略名与版本 | 归属 |
| 生成时间 | 信号生成时间戳 |
| **触发K线索引** | **溯源关键**：任何一条信号都能反查当时的数据切片与策略内部状态 |
| 参考价区间 | 价格区间 |
| 置信度 | 策略置信度 |
| 风控结论 | 通过/拒绝+原因（S07 输出） |

### 2.2 接口层（对外输出十字段，表20，**全部必填**）
| 字段 | 类型 | 必填 | 用途 |
|---|---|---|---|
| 标的代码 | 字符串 | 是 | 定位 |
| 周期 | 枚举 | 是 | 防跨周期混用 |
| 信号时间 | 日期时间 | 是 | 对齐 |
| 方向 | 枚举 | 是 | 语义 |
| 建议比例 | 浮点 | 是 | 仓位 |
| 策略标识 | 字符串 | 是 | 归属 |
| 参数哈希 | 字符串 | 是 | **可复现**（定位策略配置） |
| 快照号 | 字符串 | 是 | **可复现**（定位数据版本） |
| 依据指标 | 结构化数值 | 是 | **可验算**（手工复算同一判断） |
| 研究用途声明 | 常量 | 是 | 合规（C-029 边界） |

**十字段全部必填，不允许"空值即表示未知"**——若某项确实无法给出，接口应**返回错误而不是返回空**：空值会被下游当作正常数据参与排序与筛选，而错误会立刻暴露。

**后三项（参数哈希/快照号/依据指标）是可复现的关键**：参数哈希定位策略配置、快照号定位数据版本、依据指标让使用者手工验算。**缺少依据指标值是最常见的偷工**——只给一条"某日某标的买入"，使用者无法判断是策略生效还是框架缺陷，只能选择相信或不信；给出依据指标值后，任何人可以用原始行情复算出同一个判断，**争议从"信不信"变成"算不算得出同样的数"**。

## 3. 双分支隔离（回测/模拟物理分离）

- **回测模式**：信号只写入结果表，**不对外推送**；
- **模拟模式**：信号才进入推送队列。
- **两个分支在代码层面使用不同的出口函数，不允许通过同一个函数加布尔开关实现**——开关型实现最容易在配置错误时把回测信号推出去，而这类事故在真实项目中并不罕见。

## 4. 信号语义边界（研究用信号 ≠ 交易指令）

**本平台输出的是"研究用信号"，不是"交易指令"**。两者在数据上几乎一致，在语义上差别巨大：交易指令包含执行约束与责任承接，研究用信号只是一条带时间的判断，且明确标注不可用于自动下单。**这条边界通过四处声明落实**：接口响应字段、文档首段、报告首页、每次查询返回的提示字段。

**接口层面三条强制措施**：
1. **响应体不含券商柜台要求的必填字段组合**（委托编号、资金账号等）——从结构上阻断直接转发下单；
2. 所有信号带"**仅供研究**"标识字段，**由服务端注入，客户端不可覆盖**；
3. **接口不提供批量下单类端点**——即使被逆向工程也无法找到。

## 5. 鉴权与限流

### 5.1 鉴权三段式
| 段 | 内容 |
|---|---|
| 密钥比对 | 访问密钥由**环境变量注入，不落库、不入日志、不落任何配置文件**（密钥三不原则） |
| 时间窗校验 | **默认5分钟防重放**，超时拒绝 |
| 签名校验 | 签名覆盖**方法+路径+请求体+时间戳**，算法为带密钥的哈希 |

**鉴权请求五步走查（服务端）**：①取密钥环境变量（**缺失即启动失败，不在请求期判定**）→②比对请求头密钥摘要→③校验时间戳与服务器时间差≤5分钟→④**按固定顺序拼接方法+路径+请求体+时间戳后计算签名**→⑤比对签名。**第四步顺序必须固定并写入文档**——若顺序不定，客户端自行实现的签名与服务端不一致，错误表现为"签名错误"，排查方向会跑偏到密钥上。

### 5.2 限流（按端点分级）
| 端点 | 额度 | 分级依据（资源消耗） |
|---|---|---|
| 全量查询 | **每分钟10次** | 触发全池扫描 |
| 单标的查询 | **每分钟60次** | 只读一个小分区 |
| 提交任务 | **每分钟3次** | 启动子进程 |

**额度回收采用细粒度补充**：全量查询每分钟10次等价于**每6秒一次、桶容量3**——容量10允许瞬间突刺，一次突刺可能触发10次全池扫描，对单机服务不友好；**容量3把并发压在可接受范围**。

**限流响应必须返回剩余额度与建议等待时间，而不是简单拒绝**——静默拒绝会被使用者误判为服务故障。

### 5.3 访问日志与脱敏
- 所有请求写入访问日志：保留原始请求标识与结果，**敏感字段脱敏后入日志**（密钥/token输出为`***`，SEC-13）。

## 6. 推送与留痕

- 推送渠道：**Webhook**；**超时3秒**，失败**重试3次指数退避**。
- 每次推送记录状态：**成功/超时/被拒**。
- 推送内容=信号对象的**精简视图，不含内部参数**——避免策略参数外泄。
- 信号日志留存：全量留痕（信号标识、推送状态、时间），供审计与"信号重复推送"排查（R-006 联动）。

## 7. 失败模式（三种必须区分，不得混为一谈）

| 失败 | 判定 | 返回 | 理由 |
|---|---|---|---|
| **数据不足** | 信号所需窗口未满 | 返回**数据不足**而非"无信号" | 避免使用者以为策略已判定不动手 |
| **策略异常** | 子进程崩溃或超时 | 返回策略异常**并附日志指针** | 定位到具体策略任务 |
| **权限拒绝** | 密钥失效或额度耗尽 | 返回**明确原因与恢复方式** | 避免把额度耗尽当策略失效反复调参 |

**三者混为一谈会导致使用者在错误的方向上排查**——例如把额度耗尽当成策略失效而反复调整参数。

## 8. 错误码三分

| 类 | 示例 | 响应体建议动作 |
|---|---|---|
| **鉴权类** | 密钥缺失、签名错误、时间窗超限 | 建议检查配置 |
| **限流类** | 额度耗尽、并发超限 | 建议等待若干秒（含剩余额度） |
| **业务类** | 参数非法、策略异常 | 建议查看日志指针 |

**不加区分的统一错误码是最常见的偷懒，代价是使用者每次都要猜。**

## 9. 冲突 C-029｜信号推送与实盘边界（工程正文S08原生，项目编号顺延）

- 发现阶段：工程正文S08内部 → 项目S08（工程正文内部编号C-004；项目C-004已被滑点冲突占用，顺延为C-029）
- 冲突原文甲：S00 规定不接实盘自动交易
- 冲突原文乙：信号推送若被第三方接走并自动下单，实质等同实盘
- 量化差值：推送行为本身不越界，但下游用途不可控，边界差一个"自动下单"动作
- 风险等级：中
- 失效后果：第三方接走信号自动下单，产品实质越过合规红线，责任与资质边界失守
- 方案1：推送内容与文档**双处声明**"信号仅供研究参考，接入自动下单的风险与后果由使用者自行承担"，同时教程与商品页明确该边界

- 方案对比：方案1在保留研究信号价值的同时把边界说清，配合接口三条强制措施（无下单字段组合/仅供研究标识服务端注入/无批量下单端点）形成结构+声明双保险；方案2牺牲模拟盘核心功能
- **选定方案：方案1**
