## 1. 任务 CRUD 接口规范

| 操作 | 端点 | 说明 |
|---|---|---|
| 提交任务 | POST /api/tasks/submit | 参数+快照入唯一约束（参数哈希+快照号+策略标识），重复提交返回已有标识 |
| 查询状态 | GET /api/tasks/{id} | 返回五字段（状态/进度/最近心跳/累计耗时/失败原因） |
| 查询进度 | GET /api/tasks/{id}/progress | 已完成÷总数（保留一位小数；超1000分片显示"已完成数+总量"） |
| 取消任务 | POST /api/tasks/{id}/cancel | 写取消标志位（协作式，不杀线程） |
| 重跑任务 | POST /api/tasks/{id}/retry | 复制新参数快照，重试上限2次 |
| 查询结果 | GET /api/tasks/{id}/result | 仅成功状态可查（表24） |
| 查询日志 | GET /api/tasks/{id}/logs | 失败状态可查 |

## 2. 状态操作硬规则（表24 执行）

1. **运行中禁止改参数**——硬拦截，拒绝并记录（结果归属死结防护）；
2. **待执行/已取消禁止查结果**——无结果可查，返回明确错误而非空；
3. **成功禁止取消**——已完成为终态；
4. **失败禁止查结果**——无结果，引导查日志。

## 3. 恢复用例（A7 条件项：双中断方式）

### TC-TASK-001 杀进程中断恢复
- **场景**：运行中任务，直接杀掉工作进程（模拟崩溃/断电）。
- **断言**：任务状态**回退为待执行**（非丢失）；重启后从分片表索引**断点续跑**；已完成分片不重跑；结果路径仅在完成时写入（半成品不被当成品）。

### TC-TASK-002 协作式取消恢复
- **场景**：运行中任务发起取消，工作进程在下一个参数组合开始前检测到标志。
- **断言**：任务状态=已取消；**已产出部分结果可查看但不计入统计**；取消后资源三样（子进程/临时目录/内存映射文件）全部回收且**写回收日志**。

### TC-TASK-003 取消等待超时强制回收
- **场景**：取消后子进程20秒内不退出。
- **断言**：强制结束并**登记"强制回收"**（不静默）；半写结果文件被标记，**不被下次同参数任务误认为已完成**。

### TC-TASK-004 心跳假死判定
- **场景**：心跳超120秒未更新。
- **断言**：判定疑似失败、允许人工接管；正常繁忙任务（心跳30秒内更新）**不误判**（四倍余量生效）。

### TC-TASK-005 幂等重入
- **场景**：重复提交同参数同快照；重复取消已完成任务；重复查询进度。
- **断言**：分别返回已有标识/已完成/一致结果，**不新建、不报错、不覆盖**（唯一约束三列联合生效）。

### TC-TASK-006 超时与重试
- **场景**：任务超30分钟；失败后重试。
- **断言**：超时标记失败并记录最后完成分片索引；重试复制新快照可追溯；重试超2次进人工处理队列。

### TC-TASK-007 三级归档
- **场景**：成功任务90天/失败30天/已取消7天超期。
- **断言**：移归档表+主表软删除；归档与 S14 备份策略对齐（不出现"备份了又被归档删除"）。

### TC-TASK-008 表24 硬拦截
- **场景**：对运行中任务改参数；对成功任务取消；对失败任务查结果。
- **断言**：全部拒绝并记录原因（状态机守卫生效）。

## 4. 用例执行规范
- 8条用例进 S16 回归集；**TC-TASK-001/002 为 A7 双中断恢复核心用例**；
- 所有断言含状态字段校验（状态写数据库，进程重启后状态不丢失）；
- 归档用例与 S14 备份用例联动执行（先后顺序在 S14 验收时核对，A8 条件项：运维手册说明归档与备份的先后顺序）。
