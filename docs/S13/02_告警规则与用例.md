# S13-02｜告警规则执行与测试用例

- 文档编号：S13-02｜版本：v1.0｜日期：2026-11-13｜主责：角色7（A7），A3/A8 会签
- 工程依据：《工程正文_Doubao》S13 降噪、抑制窗口、阈值依据；评审条件（A3：**队列长度指标包含等待时长分布而不只是总数**）

---

## 1. 告警规则执行清单

| 规则 | 执行逻辑 | 数据 |
|---|---|---|
| R1 同指标合并 | 10分钟窗口内同类告警合并为一条，附计数与首次失败时间 | 告警历史 |
| R2 升级判定 | 连续失败5次升为严重并通知；单次失败仅记警告 | 失败计数 |
| R3 确认即静默 | 已确认告警修复前不重复通知；**确认必须留记录** | 确认记录 |
| R4 恢复配对 | 恢复通知与告警配对发送，不"只报坏不报好" | 告警状态机 |
| R5 抑制窗口 | 大批量提交置抑制窗口（批量÷并发×单组耗时），窗口内不因队列长度告警 | 提交事件 |
| R6 上下文三件套 | 每条告警含任务ID+错误信息+影响范围 | 任务系统 |

## 2. 用例清单（TC-MON-001~010）

### TC-MON-001 同指标10分钟合并
- **场景**：遍历任务5分钟内连续失败5次。
- **断言**：仅收到**一条**严重通知，内容含"同类失败5次+首次失败时间"；**不出现5条轰炸**。

### TC-MON-002 升级判定
- **场景**：连续失败第0次、第2次、第5次。
- **断言**：第0/2次为警告且合并计数为2；**第5次升为严重并通知**（升级阈值5次生效）。

### TC-MON-003 确认即静默
- **场景**：严重告警被确认后，故障未修复继续触发。
- **断言**：修复前不重复通知；**确认记录完整留存**（时间+确认人+告警ID）。

### TC-MON-004 恢复配对
- **场景**：故障修复。
- **断言**：**恢复通知与告警配对发送**，不出现"只报坏不报好"。

### TC-MON-005 队列抑制窗口
- **场景**：提交100组遍历任务（核数6）。
- **断言**：提交时置抑制窗口（100÷6×单组耗时估算），**窗口内不因队列长度触发严重告警**；窗口过期后异常堆积才告警。

### TC-MON-006 队列等待时长分布（A3 条件项）
- **场景**：队列有多个任务。
- **断言**：队列长度指标**包含等待时长分布而不只是总数**（如"5个任务等待>2分钟"），支撑"任务是否堆积"判断。

### TC-MON-007 数据新鲜度
- **场景**：某标的最后一次成功拉取滞后3日。
- **断言**：日线滞后1日警告、滞后3日严重；**分钟线当日内未更新即告警**；回测空跑风险被提前暴露。

### TC-MON-008 阈值取值依据
- **场景**：内存超物理八成、磁盘可用低于15%。
- **断言**：触发告警；**阈值来自配置文件非硬编码**；文档取值依据可查（内存八成=交换介入断崖；磁盘15%=5天缓冲）。

### TC-MON-009 告警上下文
- **场景**：任务失败触发告警。
- **断言**：告警含**任务ID+错误信息+影响范围**三件套，可定位到具体任务与原因。

### TC-MON-010 留存与降级
- **场景**：指标存储超磁盘预算。
- **断言**：**优先降级分钟粒度，不删除小时粒度**；历史可查（分钟7天/小时90天）。

## 3. 用例执行规范
- 10条用例进 S16 回归集；TC-MON-001/002/003/005 为降噪核心用例；
- TC-MON-006 为 A3 评审条件项落点；
- 观测开销约束：采集间隔≥10秒，用例构造时不得以高频采集模拟（监控本身不应成为负担）。
