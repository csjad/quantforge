## 2. 攻击面：三个入口

| 入口 | 风险 | 共同风险 |
|---|---|---|
| **策略代码** | 用户上传或自行编写，可执行任意逻辑 | **未经校验的外部输入直接影响内部状态** |
| **接口** | 外部可调用 | 同上 |
| **数据源** | 外部数据进入系统 | 同上 |

**审计围绕三条主线展开**：**输入校验、权限校验、状态隔离**。

## 5. 审计面五类与五要素

**审计五类对象**：接口调用、策略执行、数据变更、配置变更、导出行为。**五类均记录五要素：时间、主体、动作、对象、结果**。

**主体字段必须记录**：单机场景主体=本机使用者+会话标识，**虽只有一人仍必须记录**——未来若转多人使用，缺主体字段的历史日志无法回溯。

**表28 审计事件与留存**
| 事件 | 五要素齐全 | 留存期 | 用途 |
|---|---|---|---|
| 接口调用 | 是 | 90日 | 追溯与限流核算 |
| 策略执行 | 是 | **全周期** | 复现与责任 |
| 数据变更 | 是 | **永久** | 结果可信 |
| 配置变更 | 是 | 永久 | 复现 |
| 导出行为 | 是 | 90日 | 合规核查 |

**审计日志量级**（防过度设计）：单日回测20次×约200条事件+接口调用约50次≈日增4000条×200字节=**日增不足1MB**，90天约80MB——**单库足够，不需要独立日志系统**。

## 6. 密钥管理（三条铁律）

**不落配置文件、不进日志、不进报告**。实施=**环境变量注入+启动自检**：自检扫描配置与日志目录，**命中疑似密钥形态即启动失败并提示位置**。
**失败而不是告警**——告警会被忽略，而**密钥泄露的成本远高于一次启动失败**。

**密钥轮换四步**：生成新密钥 → **双密钥并行期（默认24小时，让在跑任务完成）** → 切换 → 吊销旧密钥。
**易错点**：并行期同时允许两把密钥时，**必须记录每次调用用的是哪把**，否则轮换后无法判断异常调用来自新旧哪一侧。

**一次密钥泄露处置四步**：立即吊销旧密钥 → 生成新密钥并注入 → **重跑受影响的接口用例** → 复盘泄露路径。**复盘必须定位到具体环节**（配置文件/日志/截图/聊天记录）——不同环节处置不同：配置文件加入自检，截图与聊天记录无法自动化，只能靠流程约束。

## 7. 越权与最小权限（入口隔离，非参数校验）

**策略沙箱、接口、面板三者权限相互独立**：
1. **策略不得读取任务表**；
2. **接口不得直接写行情分区**；
3. **面板不得调用策略执行入口**。

**三条禁止都通过"入口隔离"实现，而不是靠参数校验**——**参数校验总能被绕过，入口隔离不能**。

**越权判定示例**：策略代码尝试读任务表 → 拦截在数据访问层：**策略进程拿到的连接是只读且限定视图的，任务表不在该视图中** → 返回报错=**"对象不存在"而不是"无权限"**——前者让攻击者无法判断是权限问题还是对象问题，**后者会提示存在性**。

## 8. 不审计什么与隐私边界

**不记录**：策略源码内容、使用者输入的搜索词、浏览行为。**工具不应成为行为采集器**——审计目的是让"结果从哪来"可回答，**不是让"人做了什么"可画像**。

**隐私边界**：审计记录"谁在何时查了哪个标的的哪段时间"，**但不记录"为什么查"**（后者需使用者自述，属隐私范畴）。**审计能回答数据流向，不能回答意图，两者不应混为一谈**。
