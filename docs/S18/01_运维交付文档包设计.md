## 2. 交付包七份文档（分工不可合并）

**七份的分工不可合并**——读者与使用时机不同：

**表32 交付文档与读者**
| 文档 | 读者 | 篇幅上限 | 必备内容 |
|---|---|---|---|
| 部署手册 | 首次装机 | 20页 | 命令与样例输出 |
| 参数手册 | 日常调参 | 15页 | 参数含义与默认 |
| 开发指南 | 改策略 | 30页 | 契约与示例代码 |
| 排查手册 | 已故障 | 10页 | 症状查表 |
| 口径说明 | 对比第三方 | 8页 | 对账表 |
| 验收清单 | 交付核对 | 4页 | 逐项可勾选 |
| 变更记录 | 版本追踪 | 不定 | 兼容性标记 |

**合并成一份"用户手册"是常见做法，代价是出故障时无法快速定位到排查段**——**故障场景下人的耐心最短，此时需要的是"按症状查表"，而不是从第一章读到第九章**。

**阅读行为实测**（篇幅分配依据）：部署手册完整读概率最高（约7成）、排查手册按需查（不读全文）、开发指南只读示例段。**篇幅应向前两份倾斜，开发指南篇幅可压缩但示例必须完整**；**排查手册目录按"症状"编排而非按章节顺序**，让读者30秒内定位。

## 3. 文档可执行性三规则（硬规则）

1. **命令可复制**——命令带占位符（"路径填你的"）会导致第一步就卡住；
2. **输出有样例**——无输出样例，使用者不知道成功长什么样；
3. **失败有下一条**——失败无后续，使用者在第一个错误处停下。

**硬规则：所有命令在写作时实测一遍，把真实屏幕输出贴回去。** 实测无法省略——**凭记忆写的命令实测返工率约三成**（路径引号遗漏、参数顺序错、版本差异选项不存在），**全部实测后返工率降到不足半成**。**三成返工=一本20页手册会有6处错误，6处错误足以让读者放弃**。

**快照与截图**：界面随版本变化，**截图必须与版本绑定，文件名标注版本号**——不标版本号的截图3个版本后成为误导源，**误导比缺失更糟**。

## 4. 版本变更记录规则

每条变更记录五项：**日期、影响面、是否破坏兼容、迁移动作、回滚方式**。**破坏兼容的变更必须单独成行并在开头标记**，不允许混在列表中。

**升级风险（工程正文）**：**升级时数据库结构变更导致旧任务损坏** → 应对：**每次升级附迁移脚本并在升级前强制备份**（与 S14 六步恢复联动）。

## 5. 交付验收的仪式感

**验收清单最后一页留签字与日期栏。** 单机个人产品也需要这一栏——**理由不是法律效力，而是心理约束**：签字这个动作会让人真正把清单逐项过一遍，而只是口头说"都测过了"的人**通常跳过了三成项目**。
