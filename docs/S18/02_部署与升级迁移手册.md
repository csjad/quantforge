## 1. 部署手册：从裸机到首个回测（九步）

**判据：具备基础 Linux 知识者 30 分钟内可跑通，不符即重写该步。** 每步含：命令、预期输出、失败时回退动作。

| 步 | 动作 | 命令示例（写作时实测贴真实输出） | 预期输出 | 失败回退 |
|---|---|---|---|---|
| 1 | 系统与依赖检查 | `docker --version && docker compose version` | 版本号输出 | 装 Docker Desktop≥4.30（WSL2 后端） |
| 2 | 目录规划 | `mkdir -p ~/quantforge/{data,out,deploy}` | 目录创建成功 | 检查磁盘可用≥60GB |
| 3 | 环境变量填写 | 复制 `.env.example` 填密钥 | 文件就绪 | **缺密钥即启动失败**（S15 自检，提示位置） |
| 4 | 容器编排启动 | `docker compose up -d` | 双容器（app+备份侧车）运行 | 端口冲突→按冲突规则报错（不自动改端口，S00-01） |
| 5 | 数据库初始化 | `docker compose exec app python -m qf.init_db` | PG16 表结构就绪 | 版本不符→迁移脚本重测（PG16 锁定，S01 假设） |
| 6 | 数据导入 | 离线包导入/在线同步（首启预期"一小时左右"，S02） | 快照号生成 | 拉取失败→缺失清单+告警（不静默跳过） |
| 7 | 服务健康检查 | `curl 127.0.0.1:8000/health` | 200 响应（≤200ms） | 检查容器日志定位 |
| 8 | 首个回测提交 | 面板五动作（选策略→设参数→提交，≤3层点击，S10） | 任务进入队列 | 空态三态文案定位（数据不足≠无结果） |
| 9 | 结果核验 | 查看报告首页九项配置+三张检查图（S11） | 报告生成、配置齐全 | 报告打不开→S11 回滚机制（临时文件+原子重命名） |

**新机全流程时间账（S17 交付组口径）**：装运行时8分钟+解压样例3分钟+启动5分钟+首次回测10分钟+出报告4分钟=**30分钟，无余量**——任何一步变慢即超标。

## 2. 升级与迁移手册（A3 条件项）

**升级风险**：**升级时数据库结构变更导致旧任务损坏** → **每次升级附迁移脚本并在升级前强制备份**（S14 六步恢复联动）。

**升级流程（每次版本升级必做）**：
1. **升级前强制备份**（S14：全量每日+增量每6小时，升级触发一次额外全量）；
2. **运行迁移脚本**（结构变更脚本，**回滚方式随脚本附**）；
3. **升级后验证**：三条核心查询（标的列表/日线区间/任务状态，S14 六步第5步）；
4. **失败回退**：六步恢复流程（停止写入→选备份→校验→临时库→验证→切换）。

**A3 条件项落实**：**升级手册明确列出每次版本的结构变更点**——变更记录每条含五项（日期/影响面/**是否破坏兼容**/迁移动作/回滚方式），**破坏兼容的变更单独成行并在开头标记**。

**版本兼容说明**：
- PG 版本锁定 16（S01 假设），跨版本迁移需重测；
- 策略插件接口（五导出）为兼容基线，接口变更走破坏兼容标记；
- 报告中间层结构变更→历史报告版本比对需重渲染。

## 3. 参数调优指引（参数手册摘要）

- 调参入口：S05 参数模式声明（名称/类型/默认/上下界/步长）；
- 核心参数口径：费率0.25‰双边/印花税0.5‰卖出/滑点1‰每边/仓位30%/熔断5%（S00 B 表）；
- **参数手册给日常调参的人**：每参数含义+默认+影响（如滑点调小→收益虚高，S19 教程四坑配套）。

## 4. 日志定位指引

- 日志分层：访问日志（S08，脱敏）、任务日志（S12，含任务ID）、渲染日志（S10）、审计日志（S15，五要素）；
- 定位路径：**先按症状进故障树（S18-03）→ 按分支查日志 → 日志带任务ID/错误信息可回溯**。
