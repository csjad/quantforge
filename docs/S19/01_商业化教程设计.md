## 2. 教程读者设定（明写开篇）

**"会用电脑、不懂量化、不懂命令行"**。该设定决定全部写作取舍：
- 需要解释的名词→给类比；
- 需要输入的命令→完整可复制；
- 可能出错处→提前写"如果你看到这个报错，是因为……"。

**设低一档显得轻视读者，设高一档让真正买的人卡在第一章**。经验：**九成第一天失败发生在两处——环境变量配置、数据导入字段名**（这两处在教程中前置警示+报错修复段重点覆盖）。

## 3. 十二章结构（与 S00 R-P-003 对齐）

| 章 | 内容 | 验收方式（表33） |
|---|---|---|
| 一 | 建立动机（场景叙事） | 读者能说出用途 |
| 二 | **能做什么与不能做什么**（边界章） | 读者能说出不可自动下单 |
| 三 | 装机（硬件与系统准备） | **30分钟内跑通** |
| 四 | 导入数据（数据导入与复权设置） | 导入样例无报错 |
| 五 | 跑第一份回测（策略导入与参数含义） | 跑出首份报告、报告可打开 |
| 六 | 看懂报告（结果解读） | 能读首页九项+三张检查图 |
| 七 | 改参数（参数遍历与过拟合识别） | 会做遍历并识别过拟合 |
| 八 | 写自己的策略（风控配置+二次开发） | 能按契约写一个策略 |
| 九 | **信号输出与边界** | 明确"信号不等于交易指令" |
| 十 | 监控备份与恢复 | 完成一次巡检+备份抽检 |
| 十一 | 故障排查（症状查表） | 按症状30秒定位 |
| 十二 | 后续迭代路线 | 读者知道往哪走 |

**第二章"能做什么与不能做什么"必须排在装机之前**——排后面读者已投入半天，此时读到"不能自动下单"会觉得被误导；**排前面=一开始就划清边界**。

## 4. 每章四段模板（缺一即不合格）

1. **本节目标**——三条可验证；
2. **操作步骤**——含菜单路径与具体参数值；
3. **常见报错与修复**——**不少于5条**，格式=报错原文、原因、修复、预防；
4. **完成标志与自测题**——**缺"完成标志"会让学习者不知道自己做对没有**。

## 5. 商业化改写的边界（逐段自检）

**允许三件事**：调整叙述顺序、增加类比与截图、补充踩坑提示。
**不允许三件事**：夸大收益、隐去局限、把回测结果表述为预期收益。
**三条禁止必须写作时逐段自检——收益相关的句子最容易在润色中被写成承诺**。

## 6. 首章说服结构（关键设计）

第一章**不讲功能，讲场景**：一个具体的人，某天下班后想验证"均线交叉到底有没有用"，花两小时装平台、导入五年数据、跑出报告，发现**夏普不到一**。
**叙事落点是"验证一个想法"，而不是"赚到钱"**。
**这个选择是有意的**：首章承诺赚钱→读者第一份回测不理想时认为被骗；首章承诺验证→**第一份不理想正是预期结果，读者的信任不减反增**。

## 7. 边界章写法（第二章"不能做什么"四条并列）

1. **不能自动下单**；
2. **不能预测收益**；
3. **不能替代实盘**；
4. **不能保证数据完整**。
**四条各配一句"如果有人告诉你能，那是另一类产品"**。

## 8. 十二章篇幅分配（总约45页）

装机8页、导入5页、首份回测6页、看懂报告8页、改参数4页、写策略6页、遍历3页、稳健性4页、**报错1页（最短，只是索引，详细在排查手册）**。
