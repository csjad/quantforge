## 2. 回归范围与判据

**回归范围**：**V1 与 V2 的全部用例，另加 V3 新增的模型相关用例12条。**
**判据**：
1. **总通过率不低于95%（九成五）**；
2. **V1 核心引擎用例全部通过**（核心引擎零退化是硬底线）。

## 3. 累计基线集（防回归漏检）

**维护一份"累计基线集"，每轮改动全跑十三项：**
| 来源 | 基线项 | 数量 |
|---|---|---|
| **V1** | 五模板策略结果 | 5 |
| **V2** | 四项新增用例 | 4 |
| **V3** | 四项模型用例 | 4 |
| **合计** | | **13** |

**累计基线集的价值=防止回归漏检**：**若只跑本版新增用例，V1 的功能改动会静默退化，而退化往往发生在共享组件上——例如特征生成改了缓存键，导致 V1 的因子结果变化**。

**十三项基线耗时**：日线五模板各4秒+V2四项各5秒+V3四项各8秒=**合计约72秒**。**一分多钟的回归可在每次提交前跑，成本可接受**。

**退化的典型形态**：**共享组件改动的退化往往表现为"笔数变化百分之几"**。**缓存键调整后因子重算一次，结果偏差千分之一，笔数变化一两笔——这类变化不明显，但连续几个版本累积就会变成可观的偏差**。

## 4. 版本审计三处（任一不满足即 V3 不可发布）

| # | 审计点 | 检查方式 |
|---|---|---|
| 1 | **模型与策略的绑定是否可追溯** | 任务快照含模型版本绑定信息（A3 条件：**写入任务快照而非仅结果表**） |
| 2 | **训练区间是否全部早于回测区间** | 遍历模型注册表，训练区间与回测区间重叠即失败（C-036 校验） |
| 3 | **模型版本是否被事后替换** | 任务结束后版本锁定，替换尝试被拒绝（S28） |

## 5. 审计四份材料（缺一即审计不通过）

**四份必须同时提交，缺一即审计不通过**——**缺任何一份都会让审计者失去判断依据；例如缺遗留项清单，审计者无法知道哪些问题是已知的**。

**表45 审计材料**
| 材料 | 内容 | 作用 |
|---|---|---|
| **需求对照** | 逐条对齐 | **判定完成度** |
| **回归报告** | 十三项基线 | **判定退化** |
| **遗留清单** | 未闭环项 | **判定风险** |
| **变更记录** | 兼容标记 | **判定影响** |

## 6. 放行条件（三条）

**放行条件三条**：
1. **回归十三项全绿**；
2. **遗留项不超过五项**；
3. **破坏兼容的变更已写入教程**。
**第三条常被忽略，结果是使用者升级后发现操作方式变了却无说明。**

**放行的实际记录**：**每次放行记录五项：日期、版本、回归结果、遗留数、教程是否更新**。**五项成表可看出趋势：若遗留数逐版上升，说明迭代节奏过快**。
