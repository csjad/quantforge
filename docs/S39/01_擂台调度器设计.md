## 2. 批量提交

**一次提交一批、每批带同一快照标识**——同批共享数据快照，保证公平性四项锁中的数据快照一致。

## 3. 进度聚合

**按批次统计完成数、失败数、预计剩余时间**——擂台进度一屏可查。

## 4. 失败处理（未完成区块）

**规则**：
- **单策略失败不影响同批其他策略**；
- **失败策略保留记录但不进入榜单，在榜单末尾单列"未完成"区块并注明原因**。

**意义**：**防止"把跑失败的策略静默剔除"，那会让榜单看起来更漂亮而失真。**

## 5. 调度策略（优先级 + 最短期优先）

**擂台采用"优先级加最短期优先"混合调度：**
- **策略优先级由提交顺序决定**；
- **同优先级内选预估耗时最短的先跑**；
- **目的：让使用者尽快看到第一批结果，而不是被一个长任务堵住全部**。

**预估耗时**：**来自历史同类任务的耗时中位数，缺失时取默认值并按实际耗时更新**。

## 6. 资源隔离（共享进程池，隔离三样）

**擂台内任务共享同一进程池，但必须隔离三样：**
1. **沙箱目录**；
2. **结果文件路径**；
3. **内存配额**。

**内存配额按任务数均分，超配额即终止该任务并标记"资源不足"，而不是让整池崩溃。**

**表54 调度参数（冻结）**
| 参数 | 默认 | 说明 |
|---|---|---|
| 并行度 | 核数减二 | 与全局一致 |
| 配额 | 均分 | 超限终止 |
| 预估源 | 历史中位数 | 缺失取默认 |
| 重试 | 一次 | 仅资源类失败 |

## 7. 失败语义（不中断整场）

**擂台内单任务失败不得中断整场。**
**失败任务在对比表中占一行，标注"未完成"与原因，其余任务照常给出结果。**
**这条规则避免了"一个参数越界导致整场白跑"，而参数越界在批量提交中极其常见。**
