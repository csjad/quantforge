# S39-02｜调度参数、配额与失败语义

- 文档编号：S39-02｜版本：v1.0｜日期：2026-11-13｜主责：角色3（A3），A7 会签
- 工程依据：《工程正文_Doubao》S39 配额数值、失败不中断验证；A7 条件（**验证单策略崩溃不扩散**）

---

## 1. 配额数值（深入推导口径）

**六个任务、内存32GB，单任务配额4GB，留8GB给系统。**
- 若某任务峰值2.2GB → 配额足够；
- 若某任务因策略缓存涨到5GB → **被终止并标记"资源不足"**；
- **标记而不是静默重试，是因为重试仍会超限**。

## 2. 失败不中断的验证（A7 条件项）

**构造一个参数越界的任务混在10个正常任务中，断言：越界任务标记失败，其余9个正常给出结果。**
**这条用例是擂台可用性的底线**——参数越界在批量提交中极其常见，单任务失败绝不能拖垮整场。

**A7 条件项落实**：**验证单策略崩溃不扩散**——
- 单策略崩溃/超配额/参数越界 → 该任务标记失败，**不扩散到同批其他任务**；
- 崩溃任务的隔离三样（沙箱/路径/配额）不污染共享进程池；
- 失败任务进入"未完成"区块注明原因，其余照常出榜。

## 3. 失败类型与处置

| 失败类型 | 处置 |
|---|---|
| **参数越界** | 任务标记失败，不进入榜单，未完成区块注明 |
| **资源不足（超配额）** | 终止+标记"资源不足"，不静默重试（重试仍超限） |
| **策略崩溃/超时** | 单任务失败不中断整场，其余照常 |
| **数据快照不一致** | 拒绝入擂（不构成同一擂台，S38 四项锁） |

## 4. 预估耗时的更新机制

- **历史同类任务耗时中位数**作预估源；
- 缺失时取默认值；
- **按实际耗时更新**——预估值随运行迭代越来越准，最短期优先调度更准确。

## 5. 用例要点（S41 回归落点）
- **TC-ARENA-SCH-001 单策略失败不扩散**（A7 底线用例）：越界任务混入10正常任务→断言越界失败、其余9正常出榜；
- **TC-ARENA-SCH-002 超配额终止**：任务内存涨超配额→终止+标记资源不足，不波及同池；
- **TC-ARENA-SCH-003 优先级+最短期优先**：同优先级耗时短先跑，长任务不堵全部；
- **TC-ARENA-SCH-004 同快照标识**：批次快照标识校验，不一致拒绝入擂；
- **TC-ARENA-SCH-005 未完成区块**：失败任务占一行标注未完成+原因，不静默剔除；
- **TC-ARENA-SCH-006 预估更新**：缺失预估取默认，按实际耗时更新中位数。
