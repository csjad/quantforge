## 2. 公平性校验（四项）

**校验脚本检查四条**：
1. **同批任务的快照标识是否一致**；
2. **标的池是否一致**；
3. **费率与滑点是否一致**；
4. **基准是否一致**。

**四项中任一项不一致，擂台标记为无效并拒绝生成榜单。**

## 3. 公平性校验的五个断言（表56）

| 断言 | 触发 | 处置 |
|---|---|---|
| **快照一致** | 提交时 | 拒绝启动 |
| **费率一致** | 提交时 | 拒绝启动 |
| **区间一致** | 提交时 | 拒绝启动 |
| **脚本一致** | 提交时 | 拒绝启动 |
| **种子显式** | 提交时 | 拒绝启动 |

- **五条中第五条（种子显式）最容易被忽略**：**若某策略内部用了随机采样而未设种子，两次运行结果不同，擂台排名随即失去意义，而这种差异往往被理解为"策略不稳定"**。

## 4. 校验的时机（前置）

**校验必须在调度前完成，不能边跑边校。**
**理由：跑完再发现口径不一致，已经浪费了全部算力，且使用者会对平台产生不信任。前置校验的成本是一次配置比对，几乎为零。**

## 5. 一致性测试

**做法：同一策略提交两次，两次结果应完全一致。**
**若不一致说明存在随机性或未固定种子。**
**这条测试能暴露许多隐蔽问题，例如并行读写的顺序依赖、时间戳参与计算、浮点累加顺序不稳定。**

**复跑的一致性验证**：**抽前两名策略各复跑一次，比对十二项指标，偏差小于千分之五视为一致。若不一致，说明存在未声明的随机源，须定位并消除。复跑是发现隐性随机的唯一实用手段。**

**隐性随机的三种来源**：
1. **策略内部用了随机采样未设种子**；
2. **遍历器默认打乱了任务顺序导致浮点求和顺序不同**；
3. **缓存命中与否影响指标预热**。

**第三种最难查**：**它的偏差呈现在"有缓存与无缓存"两次运行之间，而使用者通常只跑一次**。

**复跑一致性阈值**：**千分之五**。**实测正常浮点差异在千分之一以内，千分之五给了四倍余量，超过即判定存在随机源。**
