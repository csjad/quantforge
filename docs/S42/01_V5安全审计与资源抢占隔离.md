## 2. 资源抢占测试

**风险**：**大批量提交挤占单任务资源，导致单任务超时失败。**

**测试方法**：**同时提交一个超大擂台与一个普通回测，观察普通回测是否按时完成。**

**判据**：**普通回测耗时增长不超过五成（50%），超出则须为擂台设置并发上限。**

## 3. 资源抢占的三种情形（表57）

| 场景 | 资源 | 处置 |
|---|---|---|
| **CPU 争抢** | 核 | **配额加优先级** |
| **缓存冲突** | 目录 | **只读加私有临时** |
| **导出争抢** | 磁盘 | **串行化** |
| **内存超限** | 内存 | **配额终止** |

**三种情形的处置不同**：
- **CPU争抢用配额与优先级解决**；
- **缓存目录争抢用"只读共享加各自写临时目录"解决**；
- **磁盘带宽争抢用串行化导出解决**。

**三者中第二种最容易出事**：**缓存目录被两个进程同时写会产生半写文件**。

## 4. 隔离的落地

**缓存以只读方式挂载给擂台所有任务，任何写入请求被引导到任务私有临时目录。**
**这条规则同时解决了并发读与写冲突，代价是缓存命中率略降，因为各任务无法共享新计算的结果。**

## 5. 审计两处

1. **擂台参数是否可被用于提交超出资源上限的任务**；
2. **擂台结果是否可被非法改写**。

## 6. 审计新增项（V5 两项）

1. **擂台配置快照是否随结果一同落盘**；
