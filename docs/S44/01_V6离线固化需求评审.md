## 2. 离线范围（五件事）

**五件事必须能离线完成**：**启动服务、导入样例数据、跑一次回测、生成报告、查看结果。**
**数据源在线拉取能力在离线包中默认关闭，改为本地文件导入。**

## 3. 内置清单（四项+合规底线）

**内置四项**：
1. **样例行情（自选池日线三年，约五百标的）**；
2. **三个模板策略**；
3. **一份完整教程**；
4. **一份故障排查清单**。

**合规底线**：**样例数据须为自制或公开授权，不得使用来源不明的数据，这是商品化的合规底线。**
**A2 条件项**：**样例数据附来源与授权说明。**

## 4. 体积约束

**离线包总体积控制在可下载范围，具体上限按分发渠道要求确定，超出则拆分数据包与程序包。**

## 5. 离线包的目标（可验收数字）

**目标一句话：在完全断网的新机器上，三十分钟内跑出第一份回测报告。**
**这个目标把"离线"从形容词变成了可验收的数字。**

## 6. 五个组分（缺一不可用）

| 组分 | 内容 |
|---|---|
| **组分一 运行时** | 解释器与依赖，全部本地文件 |
| **组分二 样例数据** | 五个标的五年日线与一个池的元信息 |
| **组分三 策略模板** | 五个 |
| **组分四 文档** | 七份 |
| **组分五 编排脚本** | 一键起服务 |

**五组分缺一即不可用。实践中最常缺的是样例数据**：**开发者以为使用者会自己下载，而使用者的第一台机器往往没有数据，也没有网络，于是卡在第一步。**

## 8. 明确不做

**不做在线激活、不做许可证服务器、不做使用量上报。**
**三项都会让离线包在断网环境失效或引发隐私疑虑，与本版目标直接冲突。**

## 9. 冲突 C-039｜在线源 vs 离线文件源（工程正文S44原生 C-012，项目编号顺延）

- 发现阶段：工程正文S44内部（S02 vs V6）→ 项目S44（工程正文内部编号C-012；项目C-012已被池规模冲突占用，顺延为C-039）
- 冲突原文甲：S02 的数据源抽象**以在线源为主**
- 冲突原文乙：离线包**只实现文件源，功能不对等**
- 量化差值：在线拉取能力在离线包中缺失
- 风险等级：中（功能不对等引发买家预期落差）
- 失效后果：买家以为离线包可在线拉数据，实际不能，产生"功能缺失"误解
- 方案1：**在文档中明确"离线包不含在线拉取"，并在启动检查中给出提示**
- 方案2：离线包同时内置在线源（违背断网目标）
- 方案对比：方案1诚实声明+启动提示，不违背离线定位；方案2违背断网目标
- **选定方案：方案1**
- 需回溯修改的清单：离线包文档+启动检查脚本
- 修改完成确认标记：已完成
