## 2. 产出两项（阶段任务）

1. **打包脚本**：一键产出离线包；
2. **镜像裁剪记录**：裁剪对象/处置/体积变化/验证结论的逐条留痕。

## 3. 打包脚本：四步时序（已冻结）

**打包脚本做四件事**，顺序不可乱：

| 步 | 动作 | 要点 |
|---|---|---|
| 步一 | **收集程序与依赖** | 运行时+依赖白名单收集（S44手段一：只装实际引用的库，逐条核对导入语句） |
| 步二 | **复制样例与文档** | 样例数据包+文档+策略模板+编排脚本，五组分齐备检查 |
| 步三 | **生成校验摘要** | 每个包生成校验和（见§6） |
| 步四 | **输出单一包** | 程序包（含校验和），样例数据独立成包，总体积≤200MB上限 |

## 4. 镜像裁剪：移除三部分（已冻结）

**镜像裁剪移除三部分：编译工具链、文档生成依赖、调试符号。**
**裁剪后镜像体积目标下降四成。**

**裁剪判据（铁律）**：**"裁剪后全流程仍可跑通"**——
**裁剪必须配合一次完整离线验证，不允许只验证启动。**（只验证启动会漏掉"导入时才发现缺间接依赖"这类延迟暴露的缺陷——包在启动时正常、跑一半才报错。）

## 5. 表60 裁剪清单（已冻结）

| 对象 | 处置 | 风险 |
|---|---|---|
| 测试依赖 | **移除** | 低 |
| 文档 | **分离** | 低 |
| 样例数据 | **独立包** | 中 |
| 编译缓存 | **清除** | 中 |
| **间接依赖** | **保留** | **高** |

**间接依赖是裁剪中唯一"高"风险项**：裁剪最大的风险是**漏掉某个间接依赖**，表现为**在开发机上可用、在离线机上导入失败**。处置方式=三次验证（见§7）。

## 6. 校验和与签名（已冻结）

**每个包生成校验和并写入分发说明。**
**校验和的作用不是防篡改，而是防传输损坏**：**网盘下载中断会产生一个可解压但内容缺损的包，这种包运行时报错的位置往往与真实原因无关。**

**实际案例（工程正文实测）**：**一次断点续传下载的包，解压正常但运行时报"缺少模块"。校验和比对发现文件长度少了四百千字节，重新下载后正常。这类问题若没有校验和，会花数小时排查依赖。**

## 7. 裁剪的三次验证口径（已冻结）

**裁剪必须配合三次验证**：

| 验证 | 环境 | 失败率口径 |
|---|---|---|
| 第一次 | 打包后在本机新目录解压运行 | 经验值约三成 |
| 第二次 | 在干净虚拟机运行 | 经验值约一成 |
| 第三次 | 在一台无网络配置的机器运行 | 经验值约百分之五 |

**口径区分**：S44 记录的"两成/一成/半成"是**裁剪后实测**；本表为**裁剪前经验值**——两者一致指向同一处置（字体随包分发+三次验证闭环）。

## 8. 体积压缩实测（工程正文推导，已冻结）

- **去掉测试依赖与文档**：包从 **186MB → 142MB**；
- **再清除编译缓存**：**142MB → 118MB**；
- **压缩率约三成七**；**继续压缩的空间已很小，因为运行时本身占了六十兆。**
