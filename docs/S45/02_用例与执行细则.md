# S45-02｜打包脚本执行细则与用例

- 文档编号：S45-02｜版本：v1.0｜日期：2026-11-13｜主责：角色7（A7），A8 会签
- 工程依据：《工程正文_Doubao》S45 裁剪清单/三次验证/校验和；S44 体积预算

---

## 1. 打包脚本执行流程（四步时序细则）

| 步 | 执行动作 | 通过判据 | 失败处置 |
|---|---|---|---|
| 步一 收集 | 按依赖白名单收集程序与依赖；**逐条核对导入语句**（每个 import 都有对应文件） | 白名单核对清单零缺口 | 补入缺失项后重跑，禁止盲目全量复制 |
| 步二 复制 | 复制样例数据（独立成包）+文档+策略模板+编排脚本；执行**五组分齐备检查** | 五组分齐备、缺一即报错退出 | 缺样例数据→明确提示"最常缺组分"（S44 结论） |
| 步三 摘要 | 对每个包生成**校验和**，写入分发说明 | 校验和清单齐全、与包体积同列 | 校验失败→包不分发，重新打包 |
| 步四 输出 | 输出单一程序包+独立样例数据包 | **主包≤200MB**；单一包自包含 | 超限→执行数据程序分离后再打包 |

## 2. 镜像裁剪执行细则

**移除三部分**（按表60逐项执行并留痕）：

1. **编译工具链**——移除（体积大头，运行时不需要）；
2. **文档生成依赖**——移除（离线不生成文档，运行不需要）；
3. **调试符号**——移除（体积可观，定位问题走日志非符号）。

**裁剪记录必须逐条登记**（对象/处置/裁剪前体积/裁剪后体积/验证结论），与表60一一对应；**间接依赖保留项须在记录中显式标注"保留（高）"**。

**体积核对**：裁剪后镜像体积**目标下降四成**；对照§S45-01 实测口径（186→118MB，压缩率三成七）核对，偏差过大须回查是否误删运行时必需件。

## 3. 裁剪后验证的硬性口径（A7 条件项）

**裁剪必须配合一次完整离线验证，不允许只验证启动。**
- 验证范围=**完整离线跑通**（启动→导入→回测→报告→查看，即 S44 五件事）；
- 三次验证环境（本机新目录/干净虚拟机/无网络机器）逐环境留记录；
- 任一环境失败→定位原因→修复后**三环境重跑**，不接受单环境通过即收尾。

## 4. 用例清单

| 编号 | 用例 | 通过标准 |
|---|---|---|
| **TC-PKG-001** | 四步打包时序 | 收集→复制→摘要→输出顺序执行，步间失败即停 |
| **TC-PKG-002** | 依赖白名单核对 | 逐条核对导入语句，白名单零缺口 |
| **TC-PKG-003** | 五组分齐备检查 | 缺任一分组脚本报错退出并指明缺失项 |
| **TC-PKG-004** | 体积预算 | 主包≤200MB，超限触发数据程序分离 |
| **TC-PKG-005** | 三部分裁剪+体积-40% | 编译工具链/文档生成依赖/调试符号移除，体积目标下降四成 |
| **TC-PKG-006** | 完整离线跑通（A7条件） | 裁剪后**完整离线验证**三环境通过，不只验证启动 |
| **TC-PKG-007** | 校验和防传输损坏 | 人为制造缺损包（截断400KB）→校验和比对发现→修复流程闭环 |
| **TC-PKG-008** | 间接依赖保留 | 裁剪记录中间接依赖显式标注"保留（高）"，离线机导入零失败 |

## 5. 校验和写入分发说明（验收口径）

- 分发说明中**每个包列：包名/体积/校验和/适用环境**；
- 使用者收到包**先比对校验和再解压**——传输损坏在解压前拦截，避免"报错位置与真实原因无关"的排查时间（工程正文实测：无校验和需数小时排查依赖）。
