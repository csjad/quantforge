## 5. 灾备验收的五个用例（表62，已冻结）

**五个用例覆盖的是"最坏情况下能不能救回来"，而非"平常能不能跑"。**
**这类验收在开发阶段几乎不做，而交付后一旦遇到数据损坏且无备份，用户的损失是不可逆的。**

| 用例 | 破坏方式 | 通过判据 |
|---|---|---|
| **元信息恢复** | 删库 | 标的数与快照一致 |
| **分区恢复** | 删分区 | 行数与校验和一致 |
| **配置恢复** | 清空 | 服务可启动 |
| **密钥恢复** | 失效 | 鉴权通过 |
| **整机迁移** | 新机 | 全流程可跑 |

五个用例细则：
- **用例一 元信息库损坏后恢复**：删库后按备份恢复，校验标的数与快照号；
- **用例二 行情分区损坏**：删除某月分区，按备份重挂，校验行数与校验和；
- **用例三 配置丢失**：恢复默认配置并核对差异；
- **用例四 密钥失效**：重新注入并验证鉴权；
- **用例五 整机迁移**：新机器安装后恢复全部数据。

## 6. 交付用例的写法（四段式，已冻结）

**每个用例写成四段：目的、破坏步骤、恢复步骤、判据。**
**四段必须能被第二个人照做，因此禁止"按常规方式恢复"这类表述，必须给出具体命令与路径。**

## 7. 判据的可执行化（已冻结，深入推导）

**"行数与校验和一致"必须给出具体命令与期望输出，例如"统计行数应为五千、校验和应为某十六位串"。**
**若只写"一致"，第二个人无法执行，也就无法验收。**

## 8. 五个用例的实际耗时（工程正文实测，已冻结）

| 用例 | 耗时 |
|---|---|
| 元信息恢复 | 一分钟 |
| 分区恢复 | 二十秒 |
| 配置恢复 | 十秒 |
| 密钥恢复 | 三十秒 |
| **整机迁移** | **三十五分钟** |
| **合计** | **约三十八分钟** |

**其中整机迁移占九成，因此"恢复一小时"目标的实际约束项是迁移。**
