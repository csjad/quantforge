# S49-02｜知识库条目结构、检索方式与生成草案边界

- 文档编号：S49-02｜版本：v1.0｜日期：2026-11-13｜主责：角色4（A4），A5/A7 会签
- 工程依据：《工程正文_Doubao》S49 深度展开/深入推导；C-040（C-013顺延）消解方案

---

## 1. 知识库的四类条目（库内组织，已冻结）

| 条目类型 | 内容 |
|---|---|
| **策略条目** | 规则描述加适用行情 |
| **参数条目** | 典型取值与敏感度 |
| **失败条目** | 历史上失效的案例与原因 |
| **数据条目** | 某类数据的坑 |

**口径对齐说明（非冲突）**：S49 技术正文"入库对象四类"（策略代码/参数记录/回测结果/复盘结论）是**输入侧数据对象**；本表"四类条目"是**库内组织类型**。映射关系：策略代码+回测结果→策略条目；参数记录→参数条目；复盘结论（失败案例）→失败条目；数据使用坑→数据条目。两个维度并存不冲突。

**失败条目最有价值也最少人建**：**绝大多数策略库只记录成功案例，结果是使用者反复踩同一批坑。**
**本平台要求每条失败条目写清三件事：现象、根因、以及当初的误判——第三项是防止同类误判的关键。**（失败条目必须绑定复盘结论，对接 S11 复盘五判据。）

## 2. 检索方式（已冻结）

**检索不走向量化语义搜索，走结构化过滤加关键词。**
**过滤维度为：周期、行情类型、持仓时长、以及最大回撤区间。**

**选结构化而非语义的理由是可解释：使用者能看清"为什么这条被检索出来"，而语义检索给不出理由，给不出理由的结果在专业场景中不可信。**

**检索对象受 C-040 约束**：检索字段=元数据与摘要（规则描述/适用行情/参数区间/失效原因），**代码本体加密存储且仅管理员可读，不进检索索引**。

## 3. 生成式草案的边界（已冻结）

**允许生成"规则草案"与"参数建议"，不允许生成"预期收益"。**
**前者可在沙箱中验证，后者无法验证且会误导。**
**所有草案必须标注"未验证"，并强制要求跑一次回测后才能转为正式条目。**

## 4. 生成草案的实际通过率（已冻结，必须写清）

**生成一百条草案：三十二条过静态检查（六成八因参数越界或引用不存在指标被拒）、二十一条过沙箱、十一条过小样本回测、最终一条到两条能转正。通过率约百分之一到二。**

**这个比例必须写清，因为它是"生成式策略"最容易引发落差的地方**：
- 若宣传成"一键生成策略"，九成九的失败会让使用者认为产品坏了；
- 若明确"百条取一二"，那一两条被采用时反而显得有价值。

## 5. 一条被拒草案的日志形态（已冻结）

**样例：草案引用了一个不存在的指标名，静态检查报"指标不存在"，并给出可用指标清单与相似名建议。**
**建议相似名这一步很关键，因为多数错误是拼写或改名导致，给出建议能让人一次改对。**

## 6. 转正的门槛（已冻结）

**转正要求五步全过（草案生成→静态检查→沙箱试跑→小样本回测→转正，S50 展开），且小样本回测的成交笔数不少于五笔。**
**少于五笔的草案无法判断有效性，标记为"观察中"而非转正。**

## 7. A5 条件项落实（工程原文：生成代码在沙箱内运行并限制运行时长）

- **生成代码一律在沙箱内运行**（S05 四边界全生效，双分支信号隔离不受影响）；
- **沙箱试跑设运行时长上限，超时即终止并标记**（对接 S39 擂台调度器的超时/配额语义）；
- 落点用例：TC-V7-004/005。

## 8. 用例清单

| 编号 | 用例 | 通过标准 |
|---|---|---|
| **TC-V7-001** | 四类条目入库 | 四类条目结构与映射关系落库，失败条目含三件事（现象/根因/误判） |
| **TC-V7-002** | 结构化检索 | 四维过滤（周期/行情类型/持仓时长/回撤区间）+关键词，检索结果可解释 |
| **TC-V7-003** | 代码不外泄（C-040） | 检索索引零代码明文；代码本体加密、仅管理员可读 |
| **TC-V7-004** | 沙箱内运行 | 生成代码全部经沙箱，越权/联网/超时即终止 |
| **TC-V7-005** | 运行时长上限 | 超时草案被终止并标记，不占用共享进程池 |
| **TC-V7-006** | 草案边界 | 只出规则草案与参数建议，不出预期收益；草案标注"未验证" |
| **TC-V7-007** | 通过率口径 | 通过率统计链路（静态/沙箱/回测/转正四级漏斗）可输出 |
| **TC-V7-008** | 转正门槛 | 五步全过+小样本成交笔数≥5笔才转正；不足标"观察中" |
