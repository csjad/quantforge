## 1. V8 的定位（已冻结）

**V8 是架构跃迁版，唯一目标是把单机跑批扩展为"单机加可选远程算力"。**
**触发条件是遍历组数超过一千或标的池扩至全市场。其余功能一律不为 V8 让路。**
**这个定位必须写死，否则 V8 会被塞入一堆小功能，最后既没做成集群也没做成功能。**

**V8 的触发数字（深入推导，已冻结）**：**遍历组数超过一千组，单机串行需十一小时，分片并发六路仍需两小时，超过使用者可接受的三十分钟上限。这个数字即为 V8 的触发条件。若不到一千组，集群带来的复杂度不值得。**

## 2. 表66 长期路线（已冻结）

| 版本 | 主题 | 前置依赖 | 风险 |
|---|---|---|---|
| V8 | 分布式跑批 | 无 | 中，改动面大 |
| V9 | 多用户隔离 | V8 | 高，安全 |
| V10 | 跨市场 | V8 | 中，数据层 |
| V11 | 策略共享 | V7 | 高，内容质量 |
| V12 | 自动化研究 | V8 加 V11 | 高，幻觉 |

**V9~V12 的顺序与理由**：V9 为多用户隔离（若转入售卖服务形态，权限隔离必须先于功能扩展）；V10 为跨市场扩展（港股与美股的数据结构差异会牵动数据层，宜在架构稳定后做）；V11 为策略市场（条目共享与评价，依赖 V7 知识库的成熟度）；V12 为自动化研究流水线（依赖 V8 的算力与 V11 的条目池）。
**顺序不可调换的原因在于依赖关系，而不是重要性。**

**四条依赖为何不能交换（深入推导，已冻结）**：
- **V9 在 V8 之前**：单机多用户会使权限模型与资源配额同时变复杂，而 V8 拆分后权限边界天然由进程边界承担，实现成本减半；
- **V10 在 V8 之前**：数据层每加一个市场要改一次分区策略；V8 之后分区策略已抽象，加市场只需加映射；
- **V11 依赖 V7 的条目质量**——知识库尚未成熟就共享，出来的多是半成品；
- **V12 依赖 V8 的算力与 V11 的条目池**。
**四条依赖各自有具体的技术原因，而不是"重要性排序"。**

## 3. 表67 长期路线触发条件（已冻结）

| 版本 | 触发条件 | 不达条件的处置 |
|---|---|---|
| V8 | 遍历超一千组 | 保持单机串行 |
| V9 | 有第二个使用者 | 保持单账户 |
| V10 | 出现跨市场数据需求 | 保持单市场 |
| V11 | 条目池超过两百条 | 保持本地库 |
| V12 | V8 与 V11 同时达成 | 保持人工流水线 |

## 4. 长期不变的三条（已冻结，全生命周期不变）

**不接自动下单、不承诺收益、不隐藏配置。**
**三条规定写在此处，是因为它们是抵御"功能扩张冲淡产品定义"的最后一道闸。任何新版本的需求评审都要先回答"是否触碰这三条"，触碰即否，不进入讨论。**

**执行方式（已冻结）**：**任何新需求评审先答三问：是否触碰自动下单、是否触碰收益承诺、是否触碰配置隐藏。答"是"即否决，不进入讨论环节。这条前置判断把争议挡在评审入口，而不是在详细设计阶段反复拉扯。**

## 6. 产品白皮书要点（六项，已冻结）

| 项 | 要点 |
|---|---|
| **产品定位** | 本地 A 股多策略量化回测+实盘模拟交易平台；私有化单机部署；不强制付费云端接口；本地缓存 K 线优先 |
| **能力边界** | 历史回测+模拟撮合+信号提示；**不接自动下单、不承诺收益、不隐藏配置**（三条不变）；离线包五件事可用；生成式草案"百条取一二" |
| **版本演进逻辑** | V1 基础→V2 组合/ETF→V3 模型因子→V4 跨周期→V5 擂台→V6 离线固化→V7 知识库与生成→V8~V12 按 S51 路线按依赖推进，触发条件驱动（表67），不达条件不升级 |
| **目标客群** | A 股个人散户、量化爱好者、学生参赛者；私有部署使用者；不面向机构合规场景 |
| **交付形态** | 离线交付包（程序包+独立样例数据包，主包≤200MB）；十条验收用例全过方可发货；教程+故障清单随包 |
| **合规声明** | 不构成投资建议、不承诺收益；回测不代表未来表现（滑点/手续费/流动性/幸存者偏差/过拟合影响）；数据遵守数据源条款仅个人研究；商品页与教程首章须含能力边界/不适用场景/风险声明三项，缺一不得发布（附录D 口径） |
