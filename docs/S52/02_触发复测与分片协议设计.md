## 1. 触发器（V8-04，参数化三取一）

```python
# config 新增（默认值=蓝图触发条件的 W1 等价物，全部可配）
DISTRIBUTED_TRIGGER_GROUPS = 1000      # 遍历组数阈值（表67 原口径）
DISTRIBUTED_TRIGGER_POOL = 500         # 标的池规模阈值
DISTRIBUTED_TRIGGER_SECONDS = 30 * 60  # 预估总耗时阈值（30分钟上限，表67 口径）
DISTRIBUTED_BACKEND = "auto"           # auto | serial | parallel | remote
```

**auto 判定**：`组数 ≥ 阈值 或 池规模 ≥ 阈值 或 预估耗时（组数×单组耗时基线）≥ 阈值` → 分布式；否则 **serial（现状零改动）**。单组耗时基线=历史遍历的中位数（S39 预估口径复用），缺失取实测默认。

## 2. 任务标识与分片表（V8-01，SQLite 等价 D-008 模式）

- **任务标识三段绑定**：`策略标识 + 参数哈希 + 数据快照号`（S06-01 §4.1）→ `task_id = md5(三段)`；
- **分片表** `bt_tasks`（SQLite，`data/qf.db` 扩展；Redis+PG 留部署形态）：

| 字段 | 说明 |
|---|---|
| task_id | 三段哈希（主键，天然幂等键） |
| status | **待执行/执行中/已完成**（三状态，S06-01 §4.2） |
| params_json / snapshot_id | 参数与快照绑定 |
| result_file / checksum | **已完成=结果文件存在+校验和双确认** |
| updated_at | 断点续跑时间戳 |

- **续跑硬规则**（S06-01 §4.3 冻结）：重启后"执行中"**一律回退待执行**（无法确认是否真正完成）；**不允许把执行中标为已完成**——省几十秒，代价是"有记录但结果为空"的参数把最优点指向不存在的组合。

## 3. 幂等防重执行（V8-03，A3 前置条件）

1. **结果先落盘、状态后更新**：每组结果以独立 JSON 文件写入（含参数+全部12项指标+checksum），写完才把 bt_tasks 置"已完成"——任一环节中断，重启后按"结果文件存在+校验和"判定，**天然不重算**；
2. **队列去重**：同 task_id 的重复提交在入队时直接跳过（batch 提交常见）；
3. **跨后端一致**：serial/parallel/remote 共用同一 task_id 语义与结果格式——**切换后端不产生重复执行**。

## 4. 本机并行执行器（V8-02）

- `multiprocessing.Pool(processes=物理核数−4)`（C-034 冻结），每 worker 独立引擎实例（进程隔离=沙箱第一道边界复用）；
- **内存双约束**：使用率≥85% 告警、≥95% 拒绝新任务入队（S00 资源上限表）；W1 日线任务内存上限 1.5GB/任务；
- 单组超时 **300 秒**（S06-01 §2.3 遍历口径），超时标记失败并记录断点；
- **结果可比性硬口径**：worker 内计算与串行路径**同代码同顺序**（只并行不改算），验收=双后端逐位比对（S52-01 §5）。

## 5. 抽样复核（继承 S06-01 §7，写进触发器联动）

- 池级遍历（≥500标的）改"**抽样加复核**"：50 只抽样遍历 → 前 20 组全池复核；
- 两组夏普之差通常 1~3 成；**复核后骤降为负 → 扩抽样到 150 只重做，不接受全池结果**；
- W1 触发器把"池规模"作为三条件之一——池达标时抽样复核提示自动弹出。

## 6. 远程算力协议预留（V8-05，默认关）

| 环节 | 协议要点（V8.1 启用前不实现细节） |
|---|---|
| worker 注册 | worker 上报 核数/内存/版本 → 主控分配分片（带 token，V8-06 鉴权用例挂点） |
| 分片认领 | 按 task_id 幂等认领；执行中回退语义同本机 |
| 结果回传 | 结果 JSON+校验和上传 → 主控双确认后置已完成 |
| 失败处理 | 单任务失败不影响整场（S39 失败语义复用）；重试一次仅资源类 |

**远程算力默认关的三个理由**：无远程机器时协议是死代码；鉴权面未建（V9 前置）；蓝图"可选远程算力"本就是可选语义。
