## 2. 关键验收：双后端逐位一致（S52-01 §5 硬口径）

**test_w8.TestDoubleBackend.test_bitwise_identical**：同一 seed/组数下，serial 与 parallel 两组 records 的 **params/score/train/val/flags/snapshot 逐位相等**。

**实现期真 bug（诚实记录）**：首版排序在平分时顺序不稳定（串行=组合序，并行=as_completed 完成序）→ 双后端排名不同。**修复=统一排序键**（验证分→训练夏普→参数规范化串，`sweep._rank_key` 双后端共用）——这正是"逐位一致"验收存在的价值：它逼出了一个只在双后端对照下才暴露的确定性缺陷。

## 3. CLI 冒烟（真实证据）

```
python qf.py sweep --strategy ma_cross --param fast=3:15 --param slow=30:90 \
       --mode random --groups 12 --backend parallel
→ 12 组并行完成，每组结果文件落盘 out/sweep_results/{task_id}.json
→ 过拟合标记 12/12（单年贡献/样本外失效——排名不可作结论，S43 联动）
→ checkpoint 断点续跑路径打印
```
**触发器实测**：12 组/池 5 → auto 判定 **serial**（未达阈值，保持单机——H-S52-01 行为正确）；`--backend parallel` 显式启用通过。90+11=**101 测试全绿，gate 5/5**。

## 4. 诚实边界（W8.0）

- 单组 300 秒超时以**整批 deadline** 执行（组数×300s）；逐组粒度看门狗留部署形态；
- 远程算力协议**默认关不实现**（S52-02 §6 三理由）；Redis+PG 分片留部署形态；
- 抽样复核（50→20→全池）联动触发器已定义，**执行在池规模达标时弹出提示**（W1 池=5 不触发）；
- 并行 worker 内存水位监控（85%/95%）为部署形态项——W1 任务内存以引擎上限表约束。
